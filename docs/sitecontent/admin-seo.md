# Общие SEO-поля в Django Admin

## Состав и подключение

`sitecontent/admin_seo.py` содержит `SeoAdminMixin` для `PictAdmin`, `CategoryAdmin`, `TagPictAdmin`, `SitePageAdmin` и `ArticleAdmin`. Настройка выполняется при создании поля формы, без изменения модели или схемы БД. Модуль не импортирует модели и не создаёт циклическую зависимость между приложениями.

Mixin добавляет общий класс `admin-seo-field` и подключает `pict/static/skinali/css/admin-seo-landing-fields.css` вместе с `pict/static/skinali/js/admin-seo-fields.js`. Свойство `media` дополняет штатные ресурсы admin и других mixin; просмотрщик изображений, перетягивание категорий, фильтры и Quill остаются подключены. Повторное упоминание общего CSS в существующих `Media` объединяется Django без повторной загрузки.

## Ширина и рекомендации

- `seo_h1`, `seo_title`, `seo_description`, `intro_text` и `page_description` имеют общую ширину `48em`, `box-sizing: border-box` и `max-width: 100%`. Поля изображения больше не отличаются по ширине от категорий, тегов и постоянных страниц.
- Для `seo_title` дописывается «Рекомендуемая длина: 50–60 символов».
- Для `seo_description` дописывается «Рекомендуемая длина: 140–160 символов».
- Существующие пояснения о пустых значениях, автоматически добавляемом бренде и номере страницы сохраняются. Рекомендации не являются валидацией: прежние лимиты 200/320 символов, необязательность и правила сохранения не меняются. Миграция не требуется.
- Отдельные существующие правила ширины заголовка и адреса статьи сохраняются; остальные поля формы не расширяются автоматически.

## Счётчик символов

Атрибут `data-seo-counter` добавляется полям H1, SEO-title и Meta description. JavaScript показывает «Символов: N» сразу при открытии формы, включая уже сохранённый текст и пустое значение. Обновления выполняются на событиях `input`/`change` и после сброса формы; скрытый штатным SEO-fieldset блок тоже инициализируется. Поддержано добавление форм через штатное событие `formset:added`, повторная инициализация не создаёт дубликаты.

Считаются Unicode-кодовые точки введённого значения, включая пробелы; одиночный emoji не считается двумя UTF-16 единицами. Счётчик учитывает только поле, без автоматически добавляемого публичным представлением бренда или номера страницы. `intro_text` и `page_description` расширяются, но отдельный счётчик для них не добавляется.

Счётчик размещается в блоке существующей подсказки, не заменяет её, использует `textContent`, `role=status` и `aria-live=polite`. Его ID дополняет `aria-describedby`, сохраняя ссылки на прежнюю подсказку и ошибки. При отключённом JavaScript статические рекомендации и стандартное сохранение формы продолжают работать. Дополнительных запросов к серверу, библиотек и нагрузки на БД нет.

## Проверки

`sitecontent/test_admin_seo.py` проверяет все пять admin-форм, подсказки и атрибуты, сохранение старых лимитов и пояснений, подключение общих ресурсов ровно один раз, сохранность просмотра изображений/перетягивания/Quill, расширение текстовых полей, неизменность других admin и сохранение значений вне рекомендованного диапазона.

Клиентская логика проверяется отдельными Node-тестами на имитации DOM без запуска браузера: `tests/js/admin-seo-fields.test.cjs`. Они покрывают начальный текст, ввод/вставку/очистку, Unicode и пробелы, reset, повторную и динамическую инициализацию и доступность подсказки.

```console
python manage.py test sitecontent.test_admin_seo
node --test tests/js/admin-seo-fields.test.cjs
```

Первая команда выполняется из директории с `manage.py`, вторая — из корня репозитория. Визуальная проверка в браузере выполняется только по отдельному запросу пользователя.
