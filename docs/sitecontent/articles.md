# Статьи «Полезно знать»

## Назначение и точки входа

Статьи относятся к приложению `sitecontent` и группе Django Admin «Управление сайтом».
Публичный раздел `/polezno-znat/` показывает только опубликованные статьи, по 7 на страницу,
в порядке `-published_at, -pk`. Первая карточка на каждой странице списка содержит обложку
с заголовком поверх неё; остальные — обложку, затем заголовок и краткое описание.
В каждой карточке единственная ссылка — обложка; отдельной ссылки «Читать статью» нет.
`alt` обложки берётся из заголовка статьи с обычным autoescape. Заголовок первой карточки
находится внутри ссылки и накладывается на обложку; остальные заголовки находятся вне `<a>`.
Повторно используется `pict/includes/paginator.html`; фильтров, категорий и поиска нет.
Пункт общего меню «Полезно знать» находится после «Услуг дизайнера», перед контактами,
и редактируется тем же inline-редактором меню в шапке и подвале.

`sitecontent.urls` подключается корневым URLconf перед `pict.urls`. Страница статьи имеет
маршрут `/polezno-znat/<slug>/`. Неопубликованный или неизвестный объект возвращает 404,
включая запрос суперпользователя: отдельного публичного предпросмотра нет.
Обложка, краткое описание и дата публикации на самой странице статьи не выводятся.
Дата используется только для управления порядком, не для отложенной публикации.

## Сетка и оформление списка

`articles.css` задаёт четыре колонки от ширины окна 1200 px, три — от 900 до 1199 px,
две — от 620 до 899 px, одну — до 619 px. Первая карточка занимает две колонки,
а при одной колонке — одну. CSS Grid выравнивает высоту карточек в каждом ряду
по самой высокой; высоты разных рядов могут различаться. Минимум 340 px, максимум 500 px
задаются переменными `--article-card-min-height`/`--article-card-max-height`; фиксированной
высоты нет. Обложки обычных карточек имеют пропорции 3:2 с высотой в пределах 160–220 px,
обложка первой заполняет всю карточку. Для неё кешируется миниатюра 1200×800,
для остальных — 600×400; первая загружается сразу, последующие — лениво.

Заголовок ограничен четырьмя строками, описание — пятью; длинный текст получает многоточие.
Максимальная высота содержимого вместе с обложкой укладывается в 500 px. Над заголовком
первой карточки нижняя часть обложки затемняется плавным градиентом для читаемости.
Скругление и светло-серая тень переиспользуют общий класс `content-card` из основного
`styles.css`, разделяющий оформление с существующими `.home-benefit-card`.
Тень появляется при наведении на любую часть карточки и при фокусе ссылки с клавиатуры.
Для `prefers-reduced-motion` переход отключён.

## Модели и жизненный цикл

`Article` наследует общие `SeoMetadataFields`, а `PublicationQuerySet` используется
совместно со всеми публикуемыми моделями `pict`; общий класс находится в `sitecontent/querysets.py`.

| Поле | Контракт |
|---|---|
| `title` | обязательный заголовок, максимум 200 символов |
| `summary` | обязательный обычный текст для карточки, максимум 600 символов |
| `cover` | обязательная растровая обложка в `articles/covers/` |
| `body` | HTML статьи, максимум 200 000 символов, очистка на сервере |
| `slug` | уникальный адрес из отдельно введённого текста или, если поле пустое, из заголовка; после первого сохранения неизменяемый, без случайных суффиксов |
| `is_published` | по умолчанию `False`; открывает доступ к статье и включает её в список/XML |
| `published_at` | редактируемая дата первой публикации; автоматически заполняется только при первой публикации без даты |
| `seo_title`, `seo_description` | стандартные общие SEO-поля; пустые значения используют заголовок и краткое описание |
| `updated_at` | время изменения для sitemap, не определяет порядок статей |
| `images` | служебная M2M-связь с файлами, на которые ссылается очищенный HTML |

`save()` сохраняет прежний slug даже при изменении заголовка или ручной попытке его заменить.
`slug_from_text()` нормализует русский или латинский текст: транслитерирует, приводит к нижнему
регистру, заменяет разделители дефисами и ограничивает результат 220 символами.
Для транслитерации переиспользуется `pict.models.transliterate_filename_part`; импорт выполняется
внутри метода после загрузки моделей, чтобы не образовать цикл импорта.
`full_clean()` подготавливает slug до проверки полей, а `validate_unique()` проверяет
итоговый адрес среди всех статей, включая черновики. Совпадения после транслитерации,
нормализации регистра или ограничения длины также считаются дубликатами. Ошибка показывается
у поля «Адрес статьи» с занятым адресом и просьбой ввести другой; числовой или случайный
суффикс автоматически не добавляется. Если из исходного текста нельзя получить латинский адрес,
используется `statya` с такой же проверкой. Уникальное ограничение БД сохраняется.
Проверка действует в admin-форме и при обычном ORM-сохранении; редактирование существующей
статьи не вычисляет новый адрес даже при совпадении нового заголовка с другой статьёй.
Одинаковые заголовки разрешены, если заданы разные адреса. Ранее созданные адреса с UUID
остаются неизменными. Используется прежний столбец `slug`, существующие записи не меняются.
Снятие с публикации и повторная публикация сохраняют дату; администратор может изменить её.
Обычное редактирование статьи обновляет `updated_at`, не поднимая её наверх.
Индекс `(is_published, -published_at, -id)` соответствует публичной выборке.

HTML хранится в `TextField`, отдельные файлы — в media. Quill использует Delta внутри браузера,
а форма отправляет `getSemanticHTML()`. Перед записью выполняется модельная валидация,
так что обычный ORM `save()` защищён так же, как admin-форма.

## Адрес статьи в admin

При добавлении статьи необязательное поле «Адрес статьи» расположено сразу после заголовка.
Поля заголовка и адреса используют ту же ширину `48em` и ограничение `max-width: 100%`,
что и SEO-поля, через общий `admin-seo-landing-fields.css`; правило ограничено формой статьи.
SEO-title и Meta description дополнительно используют общий [SeoAdminMixin](admin-seo.md):
подсказки 50–60 и 140–160 символов, живой счётчик и ширину `48em` без изменения лимитов.
Ресурсы Quill, поля заголовка и адреса и ограничения доступа сохраняются.
`ArticleAdminForm` использует обычный `CharField`, чтобы разрешить русский текст и пробелы,
а `clean_slug()` перед модельной проверкой вызывает общий `Article.slug_from_text()`.
Например, «Типы стекол» преобразуется в `tipy-stekol`; пустое поле использует заголовок.
При ошибке занятого адреса остальные введённые поля остаются в форме.

`ArticleAdmin.get_readonly_fields()` разрешает ввод только при создании. При редактировании
поле показывает сохранённый slug без возможности изменения; модель также сохраняет прежний
адрес при подмене значения в POST или обычном ORM-сохранении. Полный URL по-прежнему имеет
вид `/polezno-znat/<slug>/`, отдельного поля-источника в БД нет.

## Публикация в списке admin

В списке статей `ArticleAdmin` поле «Опубликовано» редактируется чекбоксом через
штатный `list_editable`, как в списках изображений и готовых работ. После изменения
чекбоксов нужно нажать «Сохранить» внизу таблицы; заголовок остаётся ссылкой на полную форму.
Массового действия снятия с публикации нет; стандартное удаление остаётся доступно.
Изменение списка разрешено только активному суперпользователю.

Штатная форма списка сохраняет только изменённые строки через модель: дата первой
публикации сохраняется при снятии и повторной публикации, для впервые опубликованного
черновика заполняется автоматически. Slug, текст и файлы сохраняются; `updated_at` статьи
и часы раздела обновляются модельными hooks и signals, а Django Admin ведёт журнал изменений.
Сохранение без изменений не обновляет даты или журнал. Снятые статьи исчезают из публичного
списка и sitemap, их страницы возвращают 404.

## Quill 2 и настройки оформления

`QuillWidget` в `widgets.py` — переиспользуемый виджет textarea с локальными Quill 2.0.3,
общим CSS содержимого и `quill-editor.js`. Исходная textarea экранирована Django;
перед заполнением виджета HTML дополнительно очищается. При отсутствии JavaScript textarea
остаётся доступной. Инициализация использует `clipboard.convert()` и `setContents()`.
После изменений и перед submit в textarea записывается семантический HTML.

Quill и BSD-3-Clause лицензия находятся в `static/sitecontent/vendor/quill/`. На публичных
страницах JavaScript редактора не подключается, обращения к CDN во время работы нет.
Из локальных CSS/JS удалены комментарии `sourceMappingURL`, ссылавшиеся на отсутствующие
карты `.map`: иначе production-сборка через `ManifestStaticFilesStorage` останавливается.
Код и лицензионные заголовки сохранены; изменение vendor-файлов описано в соседнем `README.md`.
Новые Python-зависимости: `nh3==0.3.7` в обоих корневых requirements-файлах.

Общий `article-content.css` применяется к редактору и публичной статье. Значения по умолчанию:

- шрифт сайта: `"Segoe UI", "Helvetica Neue", Arial, sans-serif`;
- цвет `#1f231f`, размер `16px`, межстрочный интервал `1.65`;
- отдельное оформление заголовков H2/H3, списков, ссылок, цитат и адаптивных изображений.

Правила заголовков внутри `.quill-field .ql-editor` переопределяют фон и отступы
`.module h2` Django Admin: заголовок текста не получает синюю плашку раздела админки.
Размеры H2/H3/H4 одинаковы в редакторе и публичной статье; отступы Quill продолжают работать.
Для всех изображений текста задано скругление 16 px через `--article-image-radius`.
Оно применяется общим CSS в редакторе и публичном выводе, включая ранее загруженные изображения,
без изменения файлов или HTML и без разрешения произвольного inline CSS.

Quill 2.0.3 при `getSemanticHTML()` заменяет каждый обычный пробел на `&nbsp;`.
Поэтому общий `sanitize_article_html()` после разбора и очистки HTML нормализует
неразрывные пробелы в обычные: слова могут переноситься целиком. Именованные,
числовые и Unicode-варианты обрабатываются одинаково; экранированный текст `&amp;nbsp;`
и HTML-примеры не декодируются повторно. Нормализация действует при сохранении,
публичном выводе и открытии редактора, включая ранее созданные статьи без пересохранения.
Намеренно неразрывные U+00A0 в статье также становятся обычными пробелами.
`overflow-wrap: anywhere` остаётся защитой для отдельных длинных слов и адресов,
которые целиком не помещаются в строке; обычные пробелы позволяют переносить текст между словами.

CSS-переменные `--article-font`, `--article-color`, `--article-font-size`,
`--article-line-height` позволяют менять общие значения без изменения сохранённых статей.
Индивидуально разрешены Arial, Georgia, моноширинный шрифт; маленький/обычный/крупный/очень
крупный текст; пять цветов `ink`, `muted`, `green`, `red`, `blue`; выравнивание и отступы.
Выделение маркером (`background`) имеет пять светлых цветов: `yellow`, `green`, `blue`,
`pink`, `orange`; первая ячейка палитры убирает выделение, по умолчанию фона нет.
Палитра приходит из `EDITOR_BACKGROUNDS` через `data-backgrounds`; цвета описаны общими
CSS-переменными `--article-highlight-*`, используемыми в тексте и ячейках палитры.
В HTML сохраняются только разрешённые классы `ql-bg-*`. Маркер доступен рядом с цветом
текста; подпись инструмента и подсказки цветов — на русском.
Шрифты, цвета и фон зарегистрированы через классовые attributor Quill. Произвольный inline CSS
не сохраняется. Набор классов проверяется сервером и имеет определения в общем CSS.
Редактор имеет русские подписи и доступное поле `role="textbox"`.

## Очистка HTML и границы безопасности

`rich_text.sanitize_article_html()` использует HTML-парсер `nh3`, а не регулярные выражения
для обработки HTML. Белый список содержит `p`, `span`, `br`, `h2`–`h4`, `strong`, `em`,
`u`, `s`, `ol`, `ul`, `li`, `blockquote`, `a`, `img`, `sub`, `sup`.

- `script`, `style`, `iframe`, `object`, `embed`, `svg`, `math`, `template` удаляются вместе с содержимым;
- комментарии, обработчики событий, `id`, `style`, `srcset`, произвольные классы и атрибуты удаляются;
- ссылки допускают внутренний абсолютный путь, якорь, `http`, `https`, `mailto`;
  `javascript`, `data`, protocol-relative URL, обратные слеши и пробельные управляющие символы исключаются;
- ссылкам добавляется `rel="noopener noreferrer"`;
- `img.src` допускает только путь текущего `MEDIA_URL` к `articles/content/<UUID>.jpg|png|webp`.
  Внешние изображения, base64 и другие media-папки исключены;
- сохранение пустого после очистки текста без допустимых изображений отвергается.

Очистка выполняется в форме, модели, при открытии виджета и перед публичным выводом.
Только результат последней очистки получает `mark_safe`. Заголовок, описание и SEO-поля
выводятся с обычным autoescape. `QuerySet.update()`, `bulk_update()` и прямой SQL обходят
модельные hooks: публичный вывод всё равно очищается, но дата/связи файлов/lastmod требуют
штатного сохранения. Библиотеку очистки и Quill необходимо поддерживать актуальными.

## Загрузка и очистка изображений

`ArticleAdmin.get_urls()` добавляет только административный POST-маршрут
`/<ADMIN_URL>/sitecontent/article/upload-image/`. Адрес получает виджет через `reverse()`.
`admin_view` проверяет сессию и CSRF; обработчик дополнительно требует активного
суперпользователя. Сотрудник со стандартными правами моделей доступа не получает.
Никаких публичных обработчиков загрузки нет.

`article_media.prepare_article_image()` одинаково проверяет обложки и файлы текста:

- максимум 5 МБ входного файла, 12 миллионов пикселей, 6000 пикселей по стороне;
- Pillow определяет фактический JPEG/PNG/WebP, а не доверяет расширению и MIME клиента;
- SVG, HTML, повреждённые и анимированные изображения отвергаются;
- файл декодируется, исправляется EXIF-ориентация, сохраняется прозрачность и удаляются метаданные;
- результат уменьшается пропорционально до 1920 × 1920 без увеличения;
- UUID и расширение назначаются сервером; код после конца исходного файла не переносится;
- `PreparedArticleImage` предотвращает повторное перекодирование между формой и моделью.

Результат сохраняется как `ArticleImage.image` в `articles/content/`, JSON содержит `url`.
Кнопка, вставка файла из буфера и перетягивание используют один серверный обработчик.
Пока файл загружается, submit блокируется с пояснением; после добавления файл можно убрать
обычным undo. Все сообщения об ошибках вставляются через `textContent`.

`ArticleHTMLReferences` читает имена файлов из очищенного HTML через `HTMLParser`.
`Article.save()` в одной транзакции синхронизирует M2M-связи. Удалённые из текста изображения
и файлы удалённой статьи очищаются после commit, только если их не использует другая статья.
Rollback не удаляет прежние файлы. Для самих файлов, обложек и миниатюр переиспользуются
сигналы `pict.signals` и общий сервис `pict.services.photo_cleanup`, расширенный папкой `articles/`.

Загрузка до сохранения формы остаётся отдельной записью. Незавершённые формы очищаются
одноразовой командой, по умолчанию выдающей только отчёт:

```console
python manage.py cleanup_article_images
python manage.py cleanup_article_images --delete
python manage.py cleanup_unused_photos --table articles --dry-run
```

Первая команда учитывает возраст записи (по умолчанию 24 часа, минимум 1) и повторно проверяет
связи перед удалением; параметры `--min-age-hours`, `--database` поддерживаются.
Вторая команда общего механизма ищет файлы без записей БД, включая обложки и файлы после rollback.
Свежие загрузки и черновики сохраняются. Ни команда удаления, ни расписание автоматически
не запускаются. Перед явной очисткой нужны проверка отчёта и резервная копия.

## SEO, миграция и нагрузка

`ArticleList` и `ArticleDetail` переиспользуют `FavoritesContextMixin`, `set_page_metadata`
и постоянные SEO-карточки из `pict.views`. Список не загружает `body` каждой статьи.
Canonical формируется от `PUBLIC_SITE_ORIGIN`; страницы пагинации имеют номер в title и canonical.
`SitePage.Code.ARTICLES` содержит SEO раздела, `ArticleSitemap` — только опубликованные статьи
с `updated_at` как lastmod. Статическая секция содержит адрес списка. Сохранение/удаление
статьи обновляет часы раздела существующими сигналами, включая снятие с публикации.

Миграция `0006_articles` создаёт две таблицы, M2M и индекс, добавляет SEO-карточку и пункт меню.
Начальный порядок равен 45 между 40 и 50. При изменённом меню сохраняется относительный
порядок прежних ссылок; при отсутствии числового промежутка номера перераспределяются.
Повторный существующий адрес раздела не дублируется. Откат удаляет новую схему и системные записи.

Миграция `0007_article_slug_input` делает существующий `slug` редактируемым и необязательным
на уровне форм, добавляет подсказку. Она меняет только состояние модели Django, не выполняет
SQL для изменения таблицы и не преобразует сохранённые адреса.

На сервере нет нового постоянного процесса и не нужен Node.js. Локальный редактор работает
в браузере администратора; HTML очищается при запросе, обложки кешируются `sorl-thumbnail`.
Ограниченное декодирование выполняется только при административной загрузке; для текущих
10–20 посетителей отдельная инфраструктура не требуется.

## Проверки и файлы

`sitecontent/test_articles.py` содержит 35 тестов: XSS и опасные URL, классы оформления,
лимиты, устойчивость очистки, адрес без суффикса, дубликаты в модели/admin (включая черновики,
транслитерацию, длину и запасной адрес), отдельный ввод адреса, одинаковые заголовки с разными адресами,
неизменность существующих slug при переименовании и подмене поля, дата, черновики, пагинация, SEO/XML,
права admin, CSRF, реальное содержимое файлов, метаданные/полезная нагрузка,
размеры и прозрачность, очистка общих файлов, rollback, забытые загрузки, нормализация пробелов Quill,
разрешённые цвета маркера и удаление произвольных классов/inline CSS.
Тест списка проверяет разделение 11 опубликованных статей на страницы по 7 и 4,
первую карточку без описания на каждой странице пагинации,
единственную ссылку на статью в карточке и отсутствие «Читать статью».
Также проверяется `alt` обложек из заголовков, заголовок первой карточки внутри ссылки
и заголовки остальных карточек вне ссылок обложек.
Тесты чекбоксов admin проверяют снятие с публикации и первую публикацию через форму списка,
сохранение даты первой публикации, неизменность строк без правок, обновление часов,
публичного списка и sitemap, журнал изменений, сохранение без изменений и отказ сотруднику
даже с правом изменения статьи.
`tests_js/quill_roundtrip.cjs` проверяет настоящий локальный Quill в jsdom без браузера:
HTML → серверный санитайзер → Quill, обычные пробелы между словами, вложенные списки, шрифты/цвета, изображения,
выбор всех пяти цветов маркера через панель и снятие выделения,
submit, загрузку с CSRF, блокировку submit до завершения и undo.

```console
python manage.py test sitecontent.test_articles
python manage.py test
node sitecontent/tests_js/quill_roundtrip.cjs <путь-к-jsdom> <путь-к-python>
```

jsdom — только необязательная зависимость кодовых проверок, не production.
Публичные шаблоны расположены в `templates/sitecontent/`, виджет — в `widgets/quill.html`;
`articles.css` оформляет список/страницу, `quill-admin.css` — панель админки.
Визуальная проверка браузером выполняется только по прямому запросу пользователя.
