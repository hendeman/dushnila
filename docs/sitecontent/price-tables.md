# Таблицы страницы «Цена»

## Назначение

Информационные таблицы редактируются в «Управлении сайтом → Таблицы страницы “Цена”»
и выводятся только на `/price/`, после калькулятора или сообщения о его недоступности.
Они независимы от настроек, тарифов, услуг и общего переключателя калькулятора.
Quill для таблиц не используется; произвольный HTML не принимается.

## Модели и миграция

`sitecontent.models.PriceTable` хранит заголовок (200 символов), подписи первой и второй
колонок (по 100; исходно «Услуга» и «Стоимость»), необязательное примечание (2000),
`is_published=False` и служебный `position`.

`PriceTableRow` связан с таблицей через FK `table`, `related_name='rows'`, `CASCADE`.
Строка содержит обязательные `description` (2000), `price` (500) и `position`.
Стоимость — обычный текст: «Бесплатно», «от 25 руб.», «По согласованию» и другие значения.
Числа и валюта не преобразуются и не участвуют в вычислениях.

Общий абстрактный `ValidatedPriceTableContent` задаёт неотрицательный индексированный
порядок, сортировку `(position, pk)`, обрезку внешних пробелов и `full_clean()` при
штатном `save()`. Пробельные обязательные поля отвергаются. Для TextField явно заданы
`MaxLengthValidator`, чтобы длина проверялась также при ORM-сохранении.
`QuerySet.update()` и `bulk_update()` обходят эти проверки, как и обычные model hooks.

Миграция `sitecontent/0011_price_tables` создаёт только две новые таблицы и FK.
Примерные услуги не загружаются. Существующие данные и тарифы сохраняются.

## Админка

`PriceTableAdmin` использует общий `SuperuserAdminMixin`: CRUD и изменение порядка
доступны только активному суперпользователю. Строки не зарегистрированы отдельным
пунктом меню; `PriceTableRowInline` позволяет добавить, изменить и удалить их в форме
таблицы. Сохраняются стандартные CSRF, атомарность формы, журнал и подтверждение удаления.
В списке таблиц видны публикация и количество строк, доступны поиск по заголовку и фильтр
публикации. Новая таблица из admin получает позицию после остальных.

`PriceTableRowForm` задаёт многострочные поля и скрытый `position`. Изменение только
позиции пустой новой формы не делает её заполненной. `PriceTableRowFormSet` разрешает
пустой черновик, но требует хотя бы одну неудалённую заполненную строку при публикации;
ошибка не сохраняет ни таблицу, ни остальные строки.

Перетягивание и стрелки ↑/↓ используют общий `pict/static/skinali/js/admin-order.js`
и CSS маркеров. `initialize()` возвращает `refresh()`, который подключает новые строки
без повторной подписки существующих обработчиков. Адаптер
`sitecontent/js/admin-price-tables.js` обновляет скрытые позиции при перестановке,
добавлении/удалении inline и перед submit. После ошибки валидации порядок восстанавливается
из присланных позиций. Шаблон `.empty-form` не участвует. Порядок строк сохраняется
штатной кнопкой «Сохранить» вместе с остальными полями.
Перед submit адаптер также восстанавливает индексы сохранённых форм перед новыми:
стандартный Django JS после удаления новой строки перенумеровывает поля по DOM,
что при перетягивании иначе нарушило бы границу `INITIAL_FORMS`. Позиции остаются
соответствующими видимому порядку; подписи и ссылки ARIA перенумеровываются вместе с полями.

Порядок таблиц сохраняется сразу POST-запросом на административный
`sitecontent_pricetable_reorder`. URL строится через namespace текущего AdminSite.
Проверяются права и CSRF; на время запроса повторное перетягивание блокируется,
при ошибке или утрате сессии DOM возвращается к прежнему порядку.

## Общий серверный порядок

`skinali/admin_order.py:reorder_admin_objects()` переиспользуется таблицами и
`CategoryAdmin`. Проверка прав и метода остаётся в вызывающем admin-view.
JSON должен содержать непустой `ordered_ids` из различных положительных целых PK;
bool, строки, дубликаты и повреждённые данные дают 400. Неизвестный/удалённый PK даёт 409.
Объекты блокируются и перенумеровываются в транзакции соответствующей базы.
При поиске/пагинации переставляются только переданные слоты; остальные записи сохраняют
своё место. Только изменённые позиции записываются через `bulk_update()`.
Необязательный callback выполняется в той же транзакции; у таблиц он обновляет часы
страницы «Цена» и пишет журнал изменения порядка. Категории сохраняют прежние URL,
права и клиентский адаптер.

## Публичный вывод и SEO

`calculator.views.price()` выбирает только опубликованные непустые таблицы и одним
`prefetch_related('rows')` загружает все их строки. Дополнительная выборка — два SQL-запроса
при наличии таблиц, один при их отсутствии; количество запросов не растёт с числом таблиц.
Контекст `price_tables` не попадает в JSON калькулятора и не влияет на его расчёт или обмен ссылками.

`sitecontent/includes/price_tables.html` выводится вне условия доступности калькулятора.
Все поля экранируются Django, переносы строк в описаниях/ценах/примечании сохраняются через
`linebreaksbr`. Пустой список не оставляет блока таблиц. Табличная семантика сохранена:
`scope='col'`, `scope='row'`, доступное название от заголовка секции.

`sitecontent/css/price-tables.css` подключается только на «Цене»: общая палитра страницы,
рамка, скругления, выделенная шапка и чередование фона. Две колонки сохраняются на телефоне;
ширины меняются с 72/28% на 62/38%, длинный текст переносится без горизонтальной прокрутки.
Настройки внешнего вида в контент не записываются.

Общие signals `pict.signals.price_table_content_changed` обновляют `SitePage.Code.PRICE`
при сохранении/удалении таблиц и строк в той же базе. Поэтому существующий sitemap
учитывает изменение содержимого, публикации и порядка. Fixtures с `raw=True` пропускаются.
Служебные массовые ORM-операции должны обновлять часы явно; административная сортировка
делает это callback общего помощника.

Для 10–20 посетителей и сервера с 1 ядром/1 ГБ RAM дополнительные процессы, библиотеки
production, Node.js или кеш не требуются.

## Проверки

`sitecontent/test_price_tables.py` проверяет ограничения и текстовые цены, каскадное удаление,
часы страницы, публикацию и независимость от калькулятора, отсутствие таблиц в других разделах,
экранирование, переносы, порядок и постоянное число запросов, CRUD inline и журнал,
атомарность ошибок, пустые формы, публикацию непустой таблицы, частичный порядок,
неверные запросы, права и CSRF.

`sitecontent/tests_js/price_table_order.cjs` выполняет настоящие общий JS и адаптер в jsdom:
стрелки, drag-and-drop, восстановление порядка, добавление и удаление строк,
повторное обновление обработчиков, CSRF запроса, блокировку и возврат DOM при ошибке.
Отдельный сценарий с настоящими jQuery/inlines.js из установленного Django проверяет
перетягивание новой строки перед сохранёнными, добавление/удаление другой строки и
восстановление корректных индексов форм перед POST.
jsdom — временная зависимость проверки, не production; браузер не запускается.

```console
python manage.py test sitecontent.test_price_tables pict.tests.CategoryOrderingAdminTests calculator.test_public
node sitecontent/tests_js/price_table_order.cjs <путь-к-jsdom>
python manage.py migrate sitecontent
```

Визуальная проверка браузером проводится только по прямому запросу пользователя.
