# Миграции приложений проекта

## Назначение

Приложение `calculator` имеет самостоятельную цепочку `0001`–`0017_service_quantity_two_decimals`: справочники материалов и единиц, отдельные singleton-карточки общих настроек и тарифов, правила лестницы для 1–6 панелей и связанные общие услуги с режимом фиксированной суммы. Межприложенных зависимостей нет; [контракт моделей и admin](../calculator/overview.md).

Сводка Python-файлов в `skinali/pict/migrations/`, `skinali/sitecontent/migrations/` и `skinali/quiz/migrations/`. Миграции `pict` образуют цепочку от `0001` до `0039`; `0025` также зависит от модели пользователя, а `0028` — от `sitecontent/0003`. У приложения управляемого содержимого своя цепочка из девяти миграций, у квиза — цепочка из пяти миграций. Их `__init__.py` пусты и только обозначают пакеты.

Текущую итоговую схему удобнее смотреть в [models.md](../pict/models.md). Этот документ нужен для истории изменения БД и выбора миграции при диагностике.

## Итог после `0039`

- `Category`, `Color`, `TagPict` — отдельные справочники с уникальными slug; `Category` дополнительно хранит индексированную управляемую позицию и сортируется по ней, `Category` и `TagPict` хранят необязательные управляемые `seo_h1`, `seo_title`, `seo_description`, `intro_text`, а `TagPict.normalized_tag` — уникальное нормализованное поисковое значение.
- `TagAlias` каскадно принадлежит одному `TagPict` и хранит исходный синоним вместе с уникальным `normalized_alias`.
- `TagSearchLemma` каскадно принадлежит ровно одному тегу или синониму и хранит индексированную лемму отдельного слова. Одинаковые леммы разных владельцев разрешены; повторы у одного владельца запрещены.
- `Pict.name` — уникальный индексированный целочисленный номер изображения; в Django Admin поле подписано «Номер изображения». `Pict.slug` уникально адресует индивидуальную страницу и после создания не меняется автоматически.
- `Pict.alt` обязателен в штатной валидации Django; новые `Pict.photo` сохраняются под транслитерированным именем из описания с добавленным значением `Pict.name`. Цифры исходного имени файла не используются.
- `Pict.page_description`, `seo_h1`, `seo_title` и `seo_description` допускают пустое значение, при котором публичная страница использует автоматический уникальный текст с номером изображения.
- `Pict.created_at` сохраняет прежнее время добавления, а `Pict.updated_at` отслеживает последующее изменение.
- Категории, цвета и теги связаны с изображениями many-to-many.
- `Pict.title` отсутствует.
- Модель сохраняет стандартную сортировку по убыванию `id`; публичный каталог, категории и цветовые фильтры явно сортируют сначала по `-is_popular`, затем по `-id`.
- `Pict.is_published` по умолчанию равен `True`; публичные выборки каталога используют только опубликованные записи.
- `Pict.is_popular` по умолчанию равен `False`; отмеченные записи выводятся перед обычными в публичном каталоге, категориях и цветовых фильтрах.
- `FinishedWork` хранит одну фотографию готовой работы, фиксированные типы стекла и скинали, необязательный цвет покраски и при необходимости ссылается на одно изображение каталога; новый или заменённый файл фотографии получает транслитерированное имя из `FinishedWork.name`, обратная связь — `Pict.finished_works`.
- Типы не создают справочных таблиц: сохранены кодами `TextChoices` в строке готовой работы. Ограничение БД требует цвет только для покраски и запрещает номер изображения для покраски и прозрачного скинали.
- Удаление связанного `Pict` не удаляет готовую работу, а обнуляет `catalog_image`.
- Готовые работы сортируются по убыванию времени создания и ID; независимый `FinishedWork.is_published` по умолчанию равен `True` и управляет публичным показом, а `updated_at` фиксирует изменения.
- `ContactRequest` хранит валидные заявки шести типов: телефонные формы используют телефон и вопрос, обычная email-форма — настоящий email и комментарий, заявка покупки дополнительно хранит проверенную связь с `Pict` и снимок номера изображения, заявка квиза связана со снимком вопросов и ответов в `QuizSubmission`, а заказ из калькулятора хранит проверенную подписанную ссылку `calculation_url`. После удаления `Pict` снимок номера сохраняется. `viewed_at` фиксирует первый просмотр в admin; новые и исторические непросмотренные заявки имеют `NULL`. Записи сортируются от новых к старым.
- `ContactRequestDelivery` независимо отслеживает каждого получателя Telegram/email-подключения; обычная доставка каскадно принадлежит заявке, тестовая содержит `test_batch_id` без заявки. Новые формы создают доставки подходящим включённым подключениям.

## `0038_tag_search_lemmas`

Миграция зависит от `pict/0037`. После создания таблицы с двумя nullable FK, check constraint единственного владельца и двумя unique constraints data-операция заполняет леммы существующих нормализованных тегов и синонимов. Теги из нескольких слов дают отдельные уникальные леммы каждого слова; русские слова разбираются первым, наиболее вероятным результатом `pymorphy3`, числа/латиница сохраняются буквально, `ё` сводится к `е`. Используется один ленивый анализатор и ограниченный кеш; владельцы читаются порциями по 200, вставки выполняются пакетами по 500. Правила зафиксированы внутри миграции и не импортируют текущий `pict.search` или методы моделей. Исходные названия, нормализованные значения, связи изображений, URL и SEO timestamps не изменяются. Откат удаляет только новую служебную таблицу. Перед `migrate` нужно установить обновлённые requirements с анализатором и русским словарём.

## Правила для ИИ-агента

- Не редактировать примененные исторические миграции для обычного изменения схемы; менять модель и создавать новую миграцию.
- Перед изменением схемы проверить [models.md](../pict/models.md), фактический `models.py` и состояние миграций через `python manage.py showmigrations pict`.
- После создания миграции добавить ее в эту таблицу и обновить итоговую схему при необходимости.
- При проблеме перехода между конкретными версиями открыть соответствующий исходный файл миграции: сводка не содержит всех сериализованных параметров полей.

## `0025_integrations`

## `0026_tag_search_terms`

Зависит от `0025_integrations` и выполняется в безопасной последовательности:

Затем удаляет старое ограничение и `area_discount_percent`. Новые ступени не создаются автоматически. Сохраняются тарифы, услуги, переключатель публикации и маркетинговые настройки. Действующая граница применения скидок описана ниже и в документации калькулятора.

Откат восстанавливает старое поле из первой строки активного режима (или 0 без скидки), затем удаляет новую таблицу и переключатель. Несколько ступеней не представимы старым единственным процентом; такой откат теряет остальные правила. [Актуальная формула и редактор](../calculator/overview.md#акционные-настройки).

## `calculator/0019_material_discount_inclusive_threshold`

Меняет только подсказки `CalculatorSettings.material_discount_mode` и `MaterialDiscountRule.area_from` через `AlterField`, без изменения структуры таблиц и сохранённых значений. В обоих режимах скидка доступна от 2 м² включительно. Разовые пороги задают общую площадь заказа; прогрессивные — номер метра: строка 2 относится ко второму м² (участок 1–2 м²), строка 3 — к третьему. При общей площади меньше 2 м² скидки нет. Например, при тарифе 100 за м² и единственной прогрессивной строке 2→10% ровно 2 м² стоят 190. Тарифы, проценты, пороги и флаги публикации сохраняются. Откат возвращает только прежние тексты подсказок; сама формула задаётся кодом Python и JavaScript. [Правила расчёта](../calculator/overview.md#акционные-настройки).

## `calculator/0020_discount_start_from_first_rule`

Снимает `calc_discount_area_gte2`, меняет default, MinValueValidator и подсказку `MaterialDiscountRule.area_from` на минимум 1, затем добавляет CHECK `calc_discount_area_gte1`. Сохранённые строки, их ID, пороги, проценты и выбранный режим не изменяются. Начало скидки определяется первой строкой активной таблицы в `material_discount_configuration()`, а не константой 2 м²; Python и JS используют её `minimum_area`. Новый default 1 относится только к созданию новых строк.

Перед откатом нужно привести сохранённые значения меньше 2 к прежнему допустимому диапазону, иначе возврат старого CHECK будет отклонён БД. Автоматической подмены или удаления таких правил нет. [Действующая формула](../calculator/overview.md#акционные-настройки).

## `calculator/0021_service_order_discounts`

Добавляет `CalculatorService.calculation_type` (standard/order_discount, default standard) и `discount_percent` Decimal(5,2) (default 0, диапазон 0–100). CHECK БД проверяют допустимый тип и диапазон процента. Существующие услуги остаются обычными с нулевым неактивным процентом; тарифы, единицы, режимы, публикация, порядок и ID сохраняются. Новые услуги автоматически не создаются. Откат удаляет два поля и ограничения: перед ним скидочные услуги следует скрыть или перевести в подходящий обычный режим, поскольку старая версия не умеет скидки на заказ. [Правила](../calculator/overview.md#услуги-со-скидкой-на-весь-заказ).

## `calculator/0022_unified_calculation_labels`

Удаляет `CalculatorService.visibility_label`: отдельная редактируемая подпись чекбокса больше не используется. `AlterField` меняет verbose_name на «Учитывать в расчете» для `CalculatorService.is_visible`, `GlassType.is_visible`, `DecorationType.is_visible` и трёх флагов `CalculatorTariffs.show_glass_type/show_decoration_type/show_stair_lifting`. Типы полей, default и сохранённые значения переключателей остаются прежними. Тарифы, проценты, материалы по умолчанию, публикация калькулятора и формула не меняются. При откате текстовое поле возвращается пустым; удалённые индивидуальные подписи не восстанавливаются. [Редактор и подписи](../calculator/overview.md#уникальные-разделы).

## `calculator/0023_minimum_order_area`

Добавляет `CalculatorSettings.minimum_order_area_sqm` (Decimal(7,2), default 0, MinValueValidator 0) и CHECK `calc_minimum_order_area_gte0`. Существующая карточка получает нейтральный ноль: минимум не включается автоматически, тарифы, скидки и флаги сохраняются. Настройка ограничивает снизу расчётную площадь материалов и услуг по площади; фактическая геометрия остаётся отдельной. Откат удаляет поле и ограничение вместе с сохранённым минимумом. [Расчёт и интерфейс](../calculator/overview.md#минимальный-заказ).
