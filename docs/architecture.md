# Архитектура проекта

## Назначение

`Skinali` — серверный Django-проект с приложением каталога `pict` и отдельным приложением управляемого содержимого `sitecontent`. Данные хранятся в SQLite, изображения каталога — в `skinali/media/photos/`, фотографии готовых работ — в `skinali/media/finished_works/`, страницы собираются Django-шаблонами.

## Структура

```text
skinali/
├── manage.py                 # CLI Django
├── db.sqlite3                # локальная база данных, исключённая из Git
├── media/
│   ├── photos/               # изображения каталога
│   ├── finished_works/       # фотографии готовых работ
│   └── cache/thumbnails/     # производные превью sorl-thumbnail
├── skinali/                  # конфигурационный пакет проекта
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   ├── wsgi.py
│   └── __init__.py
├── pict/                     # приложение каталога
│   ├── models.py
│   ├── search.py              # нормализация, разбор и ORM-поиск каталога
│   ├── sitemaps.py            # XML-карта индексируемых публичных страниц
│   ├── views.py
│   ├── urls.py
│   ├── forms.py
│   ├── context_processors.py
│   ├── templatetags/integrations.py # вставки публичного сайта
│   ├── services/
│   │   └── contact_delivery.py
│   ├── management/commands/
│   │   └── process_contact_deliveries.py
│   ├── admin.py
│   ├── apps.py
│   ├── tests.py
│   ├── migrations/
│   ├── templates/pict/
│   ├── static/skinali/
│   └── __init__.py
└── sitecontent/              # управляемое содержимое сайта
    ├── models.py             # меню, его пункты и SEO постоянных страниц
    ├── context_processors.py # видимые пункты для публичных шаблонов

    ├── apps.py
    ├── tests.py
    ├── migrations/
```

В корне репозитория также находятся исключенный из Git `.env`, локальный шаблон `.env.example` и отдельный `.env.production.example`. `settings.py` загружает файл до чтения настроек, не заменяя уже заданные системные переменные. `DJANGO_ENVIRONMENT` выбирает профиль `development` или `production` без дублирования общих Django-настроек.

Файлы `__init__.py` приложений, конфигурационного пакета и каталогов миграций пусты: они только обозначают Python-пакеты и не содержат прикладной логики.

## Основной поток запроса

1. `skinali/skinali/urls.py` направляет публичные запросы в `pict/urls.py`, `/sitemap.xml` — во встроенное sitemap-представление с `pict/sitemaps.py`, а `/robots.txt` — в небольшой текстовый ответ с правилами обхода и абсолютным адресом карты сайта.
2. `pict/urls.py` выбирает class-based или function-based view.
3. `pict/views.py` получает данные через ORM-модели из `pict/models.py`; каталог и готовые работы проходят через общую выборку `published()`. Главная, общий каталог, готовые работы, дизайнер и контакты точечно читают два SEO-поля соответствующей `sitecontent.SitePage`.
4. При наличии `q` форма и `pict/search.py` нормализуют запрос и добавляют к опубликованному каталогу глобальные AND-условия по номеру, основным тегам и их синонимам.
5. View передает queryset и дополнительный контекст в шаблон из `pict/templates/pict/`; постоянное меню больше не дублируется в представлениях.
6. Context processor `sitecontent.context_processors.site_navigation` передаёт ленивый упорядоченный QuerySet видимых пунктов и использующую его коллекцию URL. Результат одного ORM-запроса повторно применяется в шапке, подвале и проверке адреса, которая позволяет шаблону главной скрывать карточку перехода в «Наши работы» вместе с соответствующим пунктом меню; неиспользуемый контекст не обращается к БД, межзапросного кеша нет. Отдельный `pict.context_processors.site_identity` без запросов к БД передаёт единые публичные реквизиты и абсолютные URL от `PUBLIC_SITE_ORIGIN`.
7. Общий шаблон каталожной карточки запрашивает у `sorl-thumbnail` превью шириной 760 px. Первый запрос создаёт производный файл в `media/cache/thumbnails/`, последующие используют общий кеш; полноразмерный исходник остаётся ссылкой для Fancybox. В модальной карточке этот же адрес преобразуется браузером в абсолютный URL и вместе с номером изображения передаётся штатным ссылкам публикации Telegram, Viber и WhatsApp; серверные API и ключи для этого не используются.
8. Шаблон формирует HTML; медиа в режиме `DEBUG` обслуживаются корневым URLconf. В production-профиле `DEBUG=False`, Debug Toolbar и его маршрут не подключаются, а статика собирается в `skinali/staticfiles/` для отдачи внешним веб-сервером.

Sitemap содержит постоянные страницы без запросов к БД, а также категории и теги с опубликованными изображениями. Два динамических раздела выполняют по одному агрегатному запросу и используют максимальное значение `Pict.time_update` как `lastmod`; сейчас это поле фиксирует время добавления изображения. Пустые категории, пустые теги и элементы только со снятыми с публикации изображениями в XML не попадают.

Индексируемые страницы категорий и тегов поддерживают управляемые H1, основу SEO-title, meta description и вводный текст. Поля находятся в самих `Category` и `TagPict` через абстрактную модель `SeoLandingContent`; отдельной таблицы и дополнительных запросов нет. Пустые значения сохраняют автоматические метаданные, а представления централизованно добавляют к title номер страницы и бренд.

Пять постоянных разделов основного меню имеют отдельные системные записи `SitePage`: главная, каталог, готовые работы, услуги дизайнера и контакты. Каждая запись содержит только два редактируемых поля — основу SEO-title и meta description; технический код является неизменяемым первичным ключом. Пустые поля сохраняют встроенные метаданные, а заполненный title получает номер страницы и бренд в представлении. Для одной публичной страницы выполняется один короткий запрос только этих двух столбцов; при нагрузке 10–20 посетителей отдельный кеш для него не нужен. `SitePage` и каталожная `SeoLandingContent` наследуют одинаковые поля от абстрактной `sitecontent.SeoMetadataFields`, поэтому ограничения не дублируются.

Все индексируемые публичные страницы, кроме корневой, получают видимые хлебные крошки и соответствующий `BreadcrumbList` JSON-LD из одного контекстного списка. Canonical и абсолютные URL структурированных крошек строятся от `PUBLIC_SITE_ORIGIN`, поэтому не зависят от `Host` входящего запроса; видимые ссылки остаются относительными. Дополнительных запросов к БД нет, а динамические названия безопасно экранируются. Страницы с `noindex,follow` сохраняют только визуальную цепочку; структурированные данные для них не выводятся.

Главная страница выводит в `<head>` JSON-LD-граф `WebSite` и `Organization`. Сущности получают стабильные `@id` от официального origin и связаны через `publisher`; организация содержит название «ОДИУМ», основной телефон, email, абсолютный URL логотипа и официальные профили Instagram и ВКонтакте. Адрес намеренно отсутствует. Видимые реквизиты базового шаблона и JSON-LD используют один `SITE_IDENTITY`, поэтому изменение контактов не требует синхронных правок в нескольких шаблонах.

`robots.txt` запрещает обход настраиваемого пути admin и POST-обработчика контактных заявок, сообщает Яндексу о рекламных query-параметрах через `Clean-param` и ссылается на sitemap от `PUBLIC_SITE_ORIGIN`. По умолчанию публичный origin равен `https://odium.by`; в production допускается только HTTPS.

Неизвестные публичные URL при `DEBUG=False` получают автономную оформленную страницу с настоящим HTTP 404, `noindex,follow` и относительными ссылками на главную и каталог. Необработанные production-ошибки получают такую же автономную страницу с HTTP 500, `noindex,nofollow`, нейтральным сообщением и ссылкой на главную без раскрытия технических деталей. Оба дочерних шаблона используют общую аварийную оболочку с CSS и настроенным логотипом; она рендерится без объекта `request`, поэтому context processors, меню, интеграции и БД не задействуются, а canonical и JSON-LD отсутствуют.

Для избранного используется встроенная Django-сессия с backend `signed_cookies`. Браузер отправляет POST-запрос переключателю, `pict/views.py` сохраняет список первичных ключей `Pict` под ключом `favorite_pict_ids`, а Django возвращает обновленную подписанную cookie без записи сессии в SQLite. `/favorites/` загружает актуальные изображения по этим ключам и всегда отдаёт `noindex,follow` с self-canonical. Маршрут не запрещён в `robots.txt`, поэтому робот может прочитать meta-директиву. Отдельная модель избранного и авторизация для этого сценария не используются.

Контактная форма в одной короткой транзакции сохраняет `ContactRequest` и связанную Telegram-доставку со статусом `pending`. Для покупки изображения сервер проверяет скрытый первичный ключ `Pict`, сохраняет связь и отдельный снимок номера. Веб-запрос не обращается к Telegram. Одноразовая management-команда атомарно переводит готовые задачи в `processing`, завершает запись в SQLite и только затем выполняет HTTPS-запрос. Результат фиксируется отдельным коротким обновлением; временные ошибки получают расписание повторов, постоянные — статус `failed`. Такой поток не держит SQLite-транзакцию открытой во время сети и не использует Redis, Celery или фоновые потоки web-процесса.

## Основные сущности

- `SeoMetadataFields` — общий абстрактный набор SEO-title и meta description; `SitePage` — пять системных SEO-карточек постоянных разделов. `SiteMenu` — единственная системная карточка «Основное меню»; `MenuItem` — упорядоченная, видимая или скрытая одноуровневая ссылка, общая для шапки и подвала. [Подробности](sitecontent/overview.md).
- `Integration` — управляемые суперпользователем HTML/JS-вставки в три области базового шаблона; `IntegrationRevision` хранит снимки настроек и автора через `AUTH_USER_MODEL`. Одна интеграция имеет много версий. [Подробности](pict/integrations.md).

- `Pict` — изображение с уникальным числовым именем, файлом, описанием, датой добавления и флагом публикации; снятая с публикации запись остается в admin и БД, но исключается из публичных выборок.
- `FinishedWork` — готовая работа с именем, описанием, одной фотографией и независимым флагом публикации; может ссылаться на одно изображение `Pict`, а одно изображение каталога может использоваться во многих работах.
- `Category` — категория с необязательным управляемым SEO-контентом публичной страницы; связь `Pict ↔ Category` многие-ко-многим.
- `Color` — цвет; связь `Pict ↔ Color` многие-ко-многим.
- `TagPict` — основной поисковый тег с автоматически поддерживаемым уникальным нормализованным значением и необязательным управляемым SEO-контентом публичной страницы; связь `Pict ↔ TagPict` многие-ко-многим.
- `TagAlias` — однословный поисковый синоним одного `TagPict`; изображения напрямую с синонимами не связываются.
- `ContactRequest` — запись валидной заявки с типом формы, именем, необязательными телефоном/email, вопросом/комментарием, временем создания и необязательным временем первого просмотра в admin; заявка покупки дополнительно хранит необязательную связь с `Pict` и снимок его номера.
- `ContactRequestDelivery` — состояние доставки заявки по отдельному каналу, история попыток и подтверждение внешним ID сообщения; сочетание заявки и канала уникально.

Подробная схема полей и обратных связей: [pict/models.md](pict/models.md).

## Пользовательские сценарии

- `/` — главная страница; прежний `product-number` перенаправляется в новый поиск `/skinali/?q=...`.
- `/skinali/` — опубликованная часть каталога с пагинацией по 30 изображений; без `q` поддерживает фильтр `color`, с `q` выполняет глобальный поиск.
- `/skinali/<slug_cat>/` — без `q` показывает опубликованные изображения категории с опциональным фильтром цвета и управляемыми SEO-текстами; с `q` категория и цвет игнорируются, а поиск остается глобальным.
- `/tag/<tag_slug>/` — глобальная выборка опубликованных изображений выбранного тега с пагинацией по 30, счетчиком, управляемыми SEO-текстами и полной каталожной карточкой; категория, цвет и поиск здесь не применяются. Существующий пустой тег возвращает HTTP 200 с пустым состоянием и `noindex,follow`, неизвестный slug — 404.
- `/sitemap.xml` — главная, каталог, готовые работы, дизайнер, контакты, непустые категории и непустые теги; поиск, фильтры, пагинация и персональные/служебные URL исключены.
- `/robots.txt` — правила обхода технических маршрутов и ссылка на `/sitemap.xml`; GET и HEAD возвращают текстовый ответ, остальные методы отклоняются.
- `/favorites/` — персональный для текущей браузерной сессии список опубликованных избранных изображений с `noindex,follow` и self-canonical; снятые с публикации записи удаляются из сессии. Кнопка в конце непустого списка передаёт в Telegram, Viber или WhatsApp только текст с актуальными номерами оставшихся карточек, без ссылок.
- `/favorites/toggle/<pict_id>/` — POST-переключатель состояния изображения в избранном; используется JavaScript-кнопками страницы и Fancybox.
- `/contact/request/` — общий POST-обработчик формы обратного звонка, формы с вопросом, формы с обязательным email и формы покупки выбранного изображения; валидные данные сохраняются в `ContactRequest` и ставятся в устойчивую очередь Telegram, которую обрабатывает отдельная management-команда.
- `/foto-skinali-iz-stekla/` — фотогалерея опубликованных готовых работ, отсортированная по новизне и разбитая по 6 элементов на страницу; GET-параметр `category` фильтрует работы по категории связанного изображения каталога.
- `/about/` — контактные данные для двух видов заказов и статическая карта зоны обслуживания; `/designer` — страница услуг дизайнера с фиксированной ценой `5$` без обращения к внешним сервисам.
- Прежний тестовый URL `/cats/<id>/` удалён и возвращает штатный HTTP 404; публичные категории доступны только по человекочитаемым `/skinali/<slug>/`.
- `/<DJANGO_ADMIN_PATH>/` — управление каталогом и готовыми работами, просмотр и поиск сохраненных контактных заявок, а также доступный только суперпользователю раздел «Управление сайтом»; локально используется `/admin/`. Единственная карточка меню редактирует пункты строками, а таблица «Страницы сайта» — по два SEO-поля пяти постоянных разделов без возможности добавления и удаления. «Интеграции» остаются отдельным механизмом доверенного кода. В списке заявок показываются канал и статус Telegram; отдельная служебная таблица доставок скрыта, а первый просмотр заявки визуально отмечается осветлением имени.

## Внешние и инфраструктурные зависимости

Интеграции не требуют дополнительных пакетов: `{% site_integrations %}` в `pict/base.html` одним запросом выбирает включённые записи, фильтрует точные пути и повторно использует список в head и body. Код не интерпретируется как Django-шаблон. Admin использует собственные шаблоны и не подключает вставки; дополнительная проверка тега исключает namespaces `admin` и `djdt`. Пустой `templatetags/__init__.py` регистрирует пакет шаблонных тегов. Версии доступны через зарегистрированный скрытый admin-раздел и его POST-маршрут восстановления.

Управляемое содержимое также не требует внешних зависимостей: один ленивый ORM-запрос получает видимые `MenuItem` по системному коду меню, а коллекция адресов использует кеш этого же QuerySet; изменение применяется уже на следующем запросе после сохранения. Постоянная страница отдельно читает два SEO-поля по первичному ключу. Значения ссылок экранируются шаблоном и ограничены белым списком безопасных типов.

- Django `5.2.17` LTS.
- Pillow нужен для `ImageField`.
- `sorl-thumbnail 13.1.0` создаёт и кеширует уменьшенные каталожные превью без дополнительных полей моделей; стандартные `ImageField` продолжают хранить только исходники.
- `django-extensions` и `django_debug_toolbar` по умолчанию подключены только в development-профиле.
- `requests` выполняет HTTPS-вызовы Telegram Bot API из одноразовой management-команды.
- Telegram Bot API — единственный подключенный внешний канал доставки контактных заявок; токен, chat ID и необязательный строгий HTTP(S)-прокси поступают из системного окружения или корневого `.env`. Системное окружение имеет приоритет, а при заданном прокси прямой сетевой обход запрещен.
- ASGI и WSGI точки входа доступны одновременно.
- Единственный список прямых Python-зависимостей находится в корневом `requirements.txt`; `skinali/requirements.txt` подключает его через `-r ../requirements.txt`. Назначение пакетов и установка описаны в [project/dependencies.md](project/dependencies.md).

## Когда читать исходники

Открывать исходный код обязательно при изменении логики, проверке точных импортов, анализе HTML-контекста или диагностике ошибки. Этот файл предназначен для выбора нужной области, а не заменяет проверку актуальной реализации перед редактированием.
