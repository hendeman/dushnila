# Архитектура проекта

## Назначение

`Skinali` — серверный Django-проект с одним прикладным приложением `pict`. Данные хранятся в SQLite, изображения каталога — в `skinali/media/photos/`, фотографии готовых работ — в `skinali/media/finished_works/`, страницы собираются Django-шаблонами.

## Структура

```text
skinali/
├── manage.py                 # CLI Django
├── db.sqlite3                # локальная база данных
├── media/
│   ├── photos/               # изображения каталога
│   └── finished_works/       # фотографии готовых работ
├── skinali/                  # конфигурационный пакет проекта
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   ├── wsgi.py
│   └── __init__.py
└── pict/                     # приложение каталога
    ├── models.py
    ├── views.py
    ├── urls.py
    ├── forms.py
    ├── admin.py
    ├── apps.py
    ├── tests.py
    ├── migrations/
    ├── templates/pict/
    ├── static/skinali/
    └── __init__.py
```

Оба `__init__.py` и `pict/migrations/__init__.py` пусты: они только обозначают Python-пакеты и не содержат прикладной логики.

## Основной поток запроса

1. `skinali/skinali/urls.py` направляет корневые запросы в `pict/urls.py`.
2. `pict/urls.py` выбирает class-based или function-based view.
3. `pict/views.py` получает данные через ORM-модели из `pict/models.py`.
4. View передает queryset и дополнительный контекст в шаблон из `pict/templates/pict/`.
5. Шаблон формирует HTML; медиа в режиме `DEBUG` обслуживаются корневым URLconf.

Для избранного используется встроенная Django-сессия с backend `signed_cookies`. Браузер отправляет POST-запрос переключателю, `pict/views.py` сохраняет список первичных ключей `Pict` под ключом `favorite_pict_ids`, а Django возвращает обновленную подписанную cookie без записи сессии в SQLite. `/favorites/` загружает актуальные изображения по этим ключам. Отдельная модель избранного и авторизация для этого сценария не используются.

## Основные сущности

- `Pict` — изображение с уникальным числовым именем, файлом, описанием и датой добавления.
- `FinishedWork` — готовая работа с именем, описанием и одной фотографией; может ссылаться на одно изображение `Pict`, а одно изображение каталога может использоваться во многих работах.
- `Category` — категория; связь `Pict ↔ Category` многие-ко-многим.
- `Color` — цвет; связь `Pict ↔ Color` многие-ко-многим.
- `TagPict` — поисковый тег; связь `Pict ↔ TagPict` многие-ко-многим.

Подробная схема полей и обратных связей: [pict/models.md](pict/models.md).

## Пользовательские сценарии

- `/` — поиск картинки по числовому имени или части текста тега.
- `/skinali/` — полный каталог, опционально отфильтрованный GET-параметром `color`.
- `/skinali/<slug_cat>/` — категория с опциональным фильтром цвета.
- `/tag/<tag_slug>/` — изображения выбранного тега.
- `/favorites/` — персональный для текущей браузерной сессии список избранных изображений.
- `/favorites/toggle/<pict_id>/` — POST-переключатель состояния изображения в избранном; используется JavaScript-кнопками страницы и Fancybox.
- `/foto-skinali-iz-stekla/` — фотогалерея готовых работ, отсортированная по новизне и разбитая по 6 элементов на страницу.
- `/about/` и `/designer` — статические информационные страницы.
- `/admin/` — управление каталогом и готовыми работами.

## Внешние и инфраструктурные зависимости

- Django `4.1.5`.
- Pillow нужен для `ImageField`.
- `django-extensions` и `django_debug_toolbar` включены в настройки.
- ASGI и WSGI точки входа доступны одновременно.
- Основной список пакетов находится в корневом `requirements.txt`; внутри `skinali/` также существует `requirements.txt`, поэтому при работе с зависимостями нужно проверить оба файла.
