# `skinali/pict/admin.py`

## Назначение

Настраивает Django Admin для всех моделей каталога и регистрирует их на сайте admin.

## `PictAdmin`

### Список записей

- 20 записей на страницу.
- Колонки: номер, редактируемый чекбокс «Опубликовано», миниатюра, категории, цвета.
- Ссылка открывается по полю `name`.
- Поиск: точное совпадение `name`, описание `alt`, slug и `tags__tag`. Точный поиск по номеру используется в autocomplete готовых работ.
- Фильтры: публикация, время добавления, категория, цвет.
- Сортировка: `-id`.

### Форма записи

- Основной блок содержит `name`, `is_published`, обязательное `alt`, не редактируемый `slug`, `photo`, увеличенное превью, `created_at`, `updated_at`, `color`, `cat`, `tags`. Поле `name` подписано «Номер изображения». Поле описания имеет ширину `26em`, то есть на 30% больше стандартных `20em` Django Admin, и ограничено шириной доступного контейнера. При новой загрузке или замене фотографии модель формирует латинское имя оригинала из описания и значения поля «Номер изображения»; цифры исходного имени файла не учитываются, а простое редактирование описания сохранённый файл не переименовывает. Чекбокс `is_published` подписан «Опубликовано» и для новой записи включен по умолчанию. При редактировании изображения со связанными готовыми работами перед датами появляется дополнительное поле «Готовые работы» с их кликабельными миниатюрами шириной 160 px; для нового изображения и изображения без работ поле скрыто.
- `page_description`, `seo_h1`, `seo_title`, `seo_description` собраны в свернутый по умолчанию штатный блок Django Admin «SEO и текст страницы». Поля показываются по нажатию на заголовок со стрелкой; собственный JavaScript для раскрытия не используется.
- Slug заполняется после первого сохранения из описания и номера и затем остаётся стабильным. Пустые поля раскрывающегося SEO-блока используют автоматические значения публичной страницы; их заполняют только для ручной оптимизации конкретного изображения.
- Только для чтения: slug, время добавления `created_at`, время изменения `updated_at`, увеличенное превью и галерея готовых работ.
- Для `color`, `cat`, `tags` применяется горизонтальный виджет выбора.
- Используется [PictAdminForm](forms.md).

### Переименование оригиналов

- Действие списка «Переименовать файлы по описанию и номеру» доступно пользователю с правом изменения `Pict` и работает со всеми отмеченными строками.
- Для каждой записи оно повторно применяет общее правило модели к актуальному обязательному `alt` и значению поля «Номер изображения». Например, `photos/source-918.jpg` при номере `275` и описании «Яблоки на снегу» становится `photos/yabloki-na-snegu-275.jpg`.
- Файл сначала копируется в новый безопасный путь через настроенное Django storage. Только после успешной записи обновляется `Pict.photo`; при ошибке новая незавершённая копия удаляется, а старый путь остаётся рабочим.
- После успешного обновления удаляются прежний оригинал и связанные с ним кешированные превью `sorl-thumbnail`. Следующий публичный запрос создаёт превью уже для нового URL. Если целевое имя занято, storage добавляет уникальный суффикс без перезаписи чужого файла.
- Уже подходящие имена и созданные storage варианты с техническим семисимвольным суффиксом пропускаются, поэтому повторный запуск идемпотентен. Основа прежнего имени вообще не используется как источник номера. Также пропускаются исторические строки без описания, строки без `photo` и записи, исходный файл которых отсутствует в storage. Итоговое сообщение отдельно показывает количество переименованных, неизменённых, пропущенных и ошибочных записей.
- Это явная операция: обычное сохранение изменённого описания не меняет файл. После выполненного действия прежний URL оригинала перестаёт работать, поэтому массовое переименование индексируемого каталога требует заранее продуманной стратегии перенаправлений.

### Вспомогательные методы

- `get_html_photo(object)` возвращает кликабельное изображение шириной 150 px.
- `get_html_photo_fields(object)` возвращает кликабельное изображение шириной 400 px.
- `get_list_category(object)` соединяет названия категорий через запятую.
- `get_list_color(object)` соединяет названия цветов через запятую.
- `get_finished_works(object)` показывает фотографии всех записей `FinishedWork`, связанных с текущим номером изображения.

Для HTML-превью применяются `format_html` и `format_html_join`. URL берется из соответствующего `ImageField`.

## `FinishedWorkAdmin`

- Список содержит имя, редактируемый чекбокс «Опубликовано», миниатюру фотографии, тип стекла, тип скинали, дату добавления и дату изменения; новые работы находятся сверху. Номер связанного изображения и его категории в общей таблице не показываются. Доступны фильтры по публикации, типу стекла, типу скинали и дате создания.
- Форма содержит имя, включенный по умолчанию чекбокс «Опубликовано», тип стекла, тип скинали, зависимые поля, описание, одну фотографию, увеличенное превью, дату создания и дату изменения. Обе даты доступны только для чтения.
- Скрипт `admin-finished-work.js` при выборе «Печать» показывает только необязательный «Номер изображения», при выборе «Покраска» — только обязательный «Цвет покраски», а для «Прозрачное» скрывает оба поля. Скрываемый контрол очищается и отключается, поэтому устаревшее значение не попадает в POST. Серверная валидация модели и ограничение БД независимо запрещают несовместимые комбинации.
- Поле цвета имеет подсказку и placeholder `RAL 9000`; оно обязательно только для покраски.
- `catalog_image` использует `autocomplete_fields`: администратор вводит номер, а Django ищет точное совпадение по `Pict.name`.
- Если изображение каталога не выбрано, номер и категории в списке показываются как `—`.
- Превью создаются через `format_html`: 80 px в списке и 200 px в форме. Read-only превью в форме подписано «Миниатюра», чтобы отличаться от поля загрузки «Фото».
- `get_queryset()` заранее загружает связанный `Pict` и его категории через `select_related()` и `prefetch_related()`.
- Собственный `Media` расширяет ресурсы `AdminImagePreviewMixin`: на форме одновременно работают условные поля и общий модальный просмотрщик фотографии.

## `ContactRequestAdmin`

- Общий список показывает семь колонок: имя, телефон, email, тип заявки, канал, статус и время создания. Тип заявки расположен сразу после email. Канал и статус берутся из связанной Telegram-доставки; при её отсутствии выводятся `—` и «Не поставлено в очередь».
- Имя выводится собственной ссылкой на карточку заявки, поэтому состояние просмотра и цвет назначаются самому элементу `<a>`, а не вложенному тексту. До просмотра ссылка использует стандартный цвет Django Admin `#447e9b`. Первый успешный GET карточки сохраняет `ContactRequest.viewed_at`; после этого ссылка получает CSS-класс `contact-request-name--viewed` и более светлый цвет `#8baec0` во всех состояниях `link`/`visited`.
- Доступны фильтры по типу и времени создания, поиск по имени, телефону, email, вопросу и комментарию, а также точный поиск по номеру изображения.
- При открытии существующей заявки `get_fields()` оставляет пользовательские поля соответствующей формы и добавляет общие служебные поля: неизменяемый тип заявки, статус отправки в Telegram и время создания.
- Во всех карточках заявок снова присутствует встроенный read-only блок Telegram-доставки с полями «Канал», «Статус», «Попытки», «Следующая попытка», «Время отправки», «ID внешнего сообщения» и «Последняя ошибка». Добавлять или удалять доставку через этот блок нельзя; отдельная модель доставок в меню admin по-прежнему скрыта.
- Пользовательские поля карточки: для обратного звонка — имя и телефон; для вопроса — имя, телефон и вопрос; для покупки — имя, email, комментарий, номер изображения и миниатюра; для сохраняющейся формы «Сообщение по email» — имя, email и комментарий.
- Для покупки поле связи `catalog_image` заменено read-only полем «Миниатюра»: оно показывает фотографию связанного `Pict` шириной 150 px, а при удалённой связи — `—`. Номер берётся из сохранённого `image_number`.
- Action «Поставить выбранные заявки в очередь Telegram» создает отсутствующую доставку для старых заявок; уже имеющиеся доставки не дублируются.
- Action «Повторить выбранные неотправленные доставки» перенесён в список заявок и возвращает связанные Telegram-доставки `retry`/`failed` в очередь. Уже отправленные и находящиеся в обработке записи действие не затрагивает.
- На странице выводится по 50 заявок. `get_queryset()` загружает `catalog_image` через `select_related()` и доставки через `prefetch_related()`, поэтому миниатюры, канал и статус не создают N+1 запросов.
- Отдельная модель `ContactRequestDelivery` продолжает обслуживать устойчивую очередь, но больше не зарегистрирована в Django Admin и не создаёт таблицу «Доставки заявок» в меню.

## Просмотр изображений в admin

`PictAdmin`, `FinishedWorkAdmin` и `ContactRequestAdmin` используют общий `AdminImagePreviewMixin`. Он подключает `static/skinali/js/admin-image-preview.js` и `static/skinali/css/admin-image-preview.css`, а метод `render_image_preview()` формирует одинаковую кликабельную миниатюру для разных admin-таблиц.

Все миниатюры каталога, готовых работ, покупок и блока связанных работ размечены атрибутом `data-image-preview`. Клик не переходит по прямому media-URL, а открывает исходный файл в нативном модальном `<dialog>`. Изображение меньше viewport сохраняет натуральный размер; большое пропорционально вписывается в доступную область. Окно закрывается крестиком, клавишей `Esc` или кликом по затемненному окружению. При отключенном JavaScript `href` остается запасной прямой ссылкой.

## Остальные admin-классы

- `CategoryAdmin`: показывает `cat`, `slug`; slug автозаполняется из названия. Форма разделена на основные поля и блок «SEO и текст страницы» с `seo_h1`, `seo_title`, `seo_description`, `intro_text`; поиск охватывает название и эти четыре поля.
- `TagPictAdmin`: показывает основной тег, его не редактируемое `normalized_tag`, slug и собранный через запятую список синонимов; при отсутствии синонимов выводится `—`. Форма содержит такой же блок «SEO и текст страницы». Поиск охватывает исходное и нормализованное значение тега, исходные и нормализованные значения связанных синонимов и четыре SEO-поля. Slug автозаполняется из тега.
- `TagAliasInline`: табличный inline внутри формы `TagPict`. Администратор вводит одно слово в `alias`, а `normalized_alias` видит только для чтения; по умолчанию предлагается одна пустая строка. Отдельной таблицей в меню admin `TagAlias` не регистрируется.
- `TagPictAdmin.get_queryset()` заранее загружает `search_aliases`, чтобы колонка синонимов не создавала N+1 запросов.
- `ColorAdmin`: показывает `color`, `slug_color`; сортирует по названию цвета. Автозаполнение slug закомментировано.

Пустые SEO-поля означают использование автоматически сформированных значений. В `seo_title` не нужно дописывать бренд «ОДИУМ» или номер страницы: публичное представление добавляет их самостоятельно. `intro_text` хранится как обычный текст, а переносы строк превращаются в `<br>` уже в безопасно экранированном шаблоне.

## Регистрация

Зарегистрированы пары `Pict/PictAdmin`, `FinishedWork/FinishedWorkAdmin`, `ContactRequest/ContactRequestAdmin`, `Category/CategoryAdmin`, `Color/ColorAdmin`, `TagPict/TagPictAdmin`. `TagAlias` управляется только inline-формой основного тега. Модель `ContactRequestDelivery` намеренно не зарегистрирована.

## Особенности и риски

- `PictAdmin.get_queryset()` заранее загружает категории, цвета и готовые работы; `FinishedWorkAdmin` заранее загружает связанное изображение и его категории; `ContactRequestAdmin` заранее загружает изображение покупки и доставки.
- `TagPictAdmin.get_queryset()` заранее загружает поисковые синонимы.
- Совпадение нормализованного синонима с основным тегом из другой таблицы запрещается валидацией моделей, но отдельного межтабличного ограничения БД нет.
- Аргумент методов назван `object`, перекрывая встроенный тип Python, но на работу это не влияет.

## Когда читать исходник

При изменении интерфейса admin, полей формы, поиска, фильтров, превью или производительности списка.

## Интеграции и версии

Зарегистрированы `IntegrationAdmin` и `IntegrationRevisionAdmin`. Общий `SuperuserIntegrationAdminMixin` разрешает доступ только активным суперпользователям и запрещает удаление. Форма интеграции группирует три области кода, область применения и историю; каждое сохранение создаёт снимок. Версии скрыты из главного меню, доступны по ссылке из интеграции, только для чтения и с пагинацией. Собственный маршрут `pict_integrationrevision_restore` показывает подтверждение по GET и восстанавливает версию по POST с CSRF. Код экранируется во всех admin-представлениях. Подробности: [integrations.md](integrations.md).
