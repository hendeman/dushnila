# `skinali/pict/management/commands/process_contact_deliveries.py`

## Назначение и запуск

Единая одноразовая management-команда обрабатывает общую очередь заявок и тестовых сообщений для Telegram и email. Она вызывает `process_pending_deliveries()`, не содержит бесконечного цикла и не требует отдельного постоянного worker-процесса.

```console
python manage.py process_contact_deliveries
```

Аргументы:

- `--limit 20` — общий предел числа захваченных доставок за запуск;
- `--max-attempts 5` — предел попыток одной доставки;
- `--stale-after 600` — возраст оборванного `processing` в секундах для восстановления.

Все параметры должны быть положительными. Неверные значения завершаются `CommandError`. Итоговые счётчики: восстановлено, взято, отправлено, назначено на повтор, завершено ошибкой, число подключений с ошибкой настройки. Консоль не выводит токены, получателей или данные клиентов.

## Планировщик

На основном сайте Hostland фактическое расписание, проверенное 4 октября 2026 года, — раз в пять минут. Cron запускает команду:

```console
/home/host1889656/odium.by/venv/python_3.11/bin/python /home/host1889656/odium.by/projects/odium/manage.py process_contact_deliveries
```

Текущая строка cron дополнительно перенаправляет весь вывод в `/dev/null`, поэтому отдельный журнал команды не ведётся. Почтовый отчёт cron отключён. При включённых production-настройках `LOG_ALERT_*` вызовы Python logging уровня `ERROR`/`CRITICAL` из команды отправляют отдельное почтовое уведомление; статусы ошибок, записанные только в БД, его не отправляют. Web-процесс и команда читают одинаковый `.env` и ключ шифрования подключений; `.env` доступен только пользователю приложения. В preview ручную отправку проверяют только на тестовых подключениях и данных.

Команда завершает работу после одной пачки, поэтому после развёртывания обновлённого кода следующий запуск cron создаст новый Python-процесс и загрузит новую версию без перезапуска cron. Уже выполняющийся запуск может закончить работу по прежнему коду. Обновление зависимостей в серверном virtualenv выполняется при деплое; перезапуск Passenger для web/admin — отдельный шаг деплоя и не влияет на расписание cron.

## Ошибки подключения

Пустые обязательные настройки, неправильный ключ или некорректный прокси фиксируются в карточке подключения до захвата его очереди. Попытки не расходуются; другие подключения обрабатываются. Команда возвращает итоговую статистику, включая `configuration_errors`, без `CommandError` из-за отдельного подключения. Сетевая ошибка уже начатой отправки сохраняется в конкретной доставке и обрабатывается политикой повторов.

Поэтому одного успешного кода завершения команды недостаточно для подтверждения доставки всех заявок: состояния видны в admin. Telegram-подключение, созданное миграцией, продолжает читать `TELEGRAM_*`. Подключения с секретами из admin требуют `LEAD_DELIVERY_ENCRYPTION_KEYS`; см. [настройку шифрования](../sitecontent/lead-processing.md).
