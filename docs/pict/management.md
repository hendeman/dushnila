# `skinali/pict/management/commands/process_contact_deliveries.py`

## Назначение

Одноразовая management-команда отправляет готовые контактные заявки в Telegram. Она не запускает собственный бесконечный цикл и подходит для cron или `systemd timer`.

## Запуск

Из каталога `skinali/`:

```console
python manage.py process_contact_deliveries
```

При обычном запуске настройки автоматически читают корневой `.env`; в нем должны быть заполнены `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Уже заданные системные переменные имеют приоритет над файлом. Дополнительные параметры:

- `--limit 20` — максимальный размер пачки;
- `--max-attempts 5` — число попыток до окончательного `failed`;
- `--stale-after 600` — возраст незавершенного `processing` в секундах, после которого задача возвращается в очередь.

Команда выводит только итоговые счетчики: восстановлено, взято, отправлено, назначено на повтор и завершено ошибкой. Токен, chat ID, телефон и текст вопроса в консоль не выводятся.

## Планировщик

Рекомендуемый интервал для текущей нагрузки — одна минута. Планировщик должен запускать именно одноразовую команду, а не web-процесс. Условный атомарный захват строки защищает от одновременной отправки одной задачи, если два запуска кратковременно пересекутся.

На Hostland команда запускается абсолютными путями, поэтому ей не нужны `source` и зависимости от рабочего каталога:

```console
/home/host1889656/host1889656.hostland.pro/venv/python_3.11/bin/python /home/host1889656/host1889656.hostland.pro/projects/odium/manage.py process_contact_deliveries
```

В панели выбираются «Произвольная команда» и выполнение каждую минуту. Почтовый отчёт отключается: команда пишет итоговые счётчики при каждом успешном запуске, даже если очередь пуста, поэтому включённый отчёт создавал бы письмо ежеминутно. Ошибки доставки сохраняются в самой очереди и видны в Django Admin. Команда читает `.env` из каталога приложения; права на файл должны разрешать чтение только пользователю приложения.

## Ошибки конфигурации

Если токен, chat ID или корректные тайм-ауты отсутствуют либо URL прокси некорректен, команда завершается через `CommandError` до захвата задач. Все доставки остаются в исходном состоянии и смогут быть обработаны после исправления окружения. Если конфигурация корректна, но строгий прокси недоступен, конкретная доставка получает статус `retry`; прямого обхода прокси нет.
