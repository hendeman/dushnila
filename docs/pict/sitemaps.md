# `skinali/pict/sitemaps.py`

## Назначение

Формирует XML-карту индексируемых постоянных страниц, индивидуальных страниц изображений, категорий и тегов для корневого маршрута `/sitemap.xml`.

## `PublicOriginSitemap`

Общий базовый класс всех секций переопределяет формирование абсолютных URL. Для каждого построения он читает актуальный `PUBLIC_SITE_ORIGIN`, разделяет его на HTTPS-схему и домен и передаёт их стандартному механизму Django Sitemap. Поэтому все `<loc>` используют официальный origin, по умолчанию `https://odium.by`, независимо от `Host` и схемы входящего запроса. Дополнительных запросов к БД это не создаёт.

## `StaticViewSitemap`

- Возвращает именованные маршруты `home`, `skinali`, `finished_works`, `designer` и `about`.
- Одним запросом читает `updated_at` пяти системных `SitePage` и использует соответствующее значение как `lastmod` каждого маршрута.
- URL разрешаются через `reverse()` и поэтому учитывают фактическую конфигурацию маршрутов, включая отсутствие завершающего слеша у `/designer`.
- Указывает `changefreq='monthly'` и `priority=0.5`.

## `PublishedPictureSitemap`

Общий базовый класс для динамических разделов каталога:

- модель и имя ORM-связи задаются подклассом;
- один агрегатный queryset выбирает только элементы, связанные хотя бы с одним опубликованным `Pict`, и загружает из самих справочников только slug и timestamp;
- пустые элементы и элементы только со снятыми с публикации изображениями исключаются;
- результаты сортируются по slug для стабильного XML;
- `lastmod` выбирается как более позднее значение между собственным `updated_at` категории/тега и максимальным `Pict.updated_at` опубликованных изображений. Поэтому учитываются как SEO-тексты посадочной страницы, так и её каталожное содержимое.

`CategorySitemap` использует модель `Category`, обратную ORM-связь `pict` и `priority=0.7`. `TagSitemap` использует `TagPict`, связь `tags` и `priority=0.6`. Оба раздела получают `changefreq='weekly'`; относительные пути формируются существующими `get_absolute_url()`, а общий базовый класс добавляет официальный origin. Поисковые синонимы отдельных страниц не создают.

## `PictureSitemap`

- Возвращает по одному HTML-URL для каждого опубликованного `Pict`; снятые с публикации изображения исключаются.
- Загружает только `slug` и `updated_at`, сортирует по slug и использует `Pict.get_absolute_url()` для относительного адреса.
- `lastmod` равен `Pict.updated_at`, `changefreq='monthly'`, `priority=0.8`.
- Это адреса индивидуальных HTML-страниц, а не прямые media-URL оригиналов.

Для планируемых примерно 8000 изображений и 10–20 одновременных посетителей отдельный кеш sitemap сейчас не требуется: постоянная секция выполняет один короткий запрос пяти timestamp, секция изображений — COUNT и выборку текущей страницы только из двух столбцов, а стандартный пагинатор Django делает такие же ограниченные запросы для категорий и тегов. При существенном росте поисковых роботов или каталога можно добавить HTTP-кеширование без изменения публичных URL.

## Подключение

- `django.contrib.sitemaps` зарегистрирован в `INSTALLED_APPS`.
- `skinali/skinali/urls.py` передает встроенному sitemap-представлению секции `static`, `categories`, `tags` и `pictures`.
- Тот же корневой URLconf публикует абсолютный адрес `/sitemap.xml` в `/robots.txt`; как этот адрес, так и все `<loc>` карты берут домен из проверенного `PUBLIC_SITE_ORIGIN`.
- Поиск, цветовые фильтры, пагинация, избранное, admin, тестовый маршрут и POST-обработчики намеренно не включаются.
