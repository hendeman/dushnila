# `skinali/pict/tests.py`

## Назначение

Стандартный модуль Django для тестов приложения `pict`.

Дополнительный модуль `pict/test_photo_cleanup.py` проверяет общий сервис очистки, отложенные commit-callback и команду `cleanup_unused_photos`; [подробности проверок](photo-cleanup.md#тесты). Тесты переименования фотографий в этом модуле выполняют commit-callback через `captureOnCommitCallbacks(execute=True)`, поскольку обычный `TestCase` откатывает внешнюю транзакцию.

Проверки `--table` покрывают отчёт и удаление для каждой таблицы отдельно, отсутствие обхода невыбранной папки, режим обеих таблиц по умолчанию/`all`, сохранение межтабличных ссылок и отклонение неизвестной таблицы до поиска файлов. Общий сканер также отвергает неподдерживаемые корневые папки.

Класс `AdminPhotoRenameCanonicalNameTests` в `pict/test_photo_cleanup.py` проверяет для обеих admin-таблиц переход с семисимвольного суффикса на свободное точное имя, сохранение суффикса при занятой цели, повторный запуск после освобождения имени, очистку старых миниатюр и пропуск отсутствующего исходника. Групповые тесты одинаковых имён готовых работ проверяют занятость цели после первого переименования, сохранение второго уже допустимого суффикса или выделение нового, сохранность содержимого обоих файлов и повторный запуск без изменений. Отдельно моделируется появление чужого файла между проверкой доступности и `storage.save()`.

## Текущее состояние

`AdminImagePreviewValidationTests` проверяет общую защиту миниатюр для `PictAdmin` и `FinishedWorkAdmin`: пустые формы; HTML-разметку сообщения о несохранённом изображении и штатный цвет ошибок `var(--error-fg)` из общего CSS; отсутствие URL, запросов к БД и вызовов `sorl-thumbnail` для несохранённого файла; снимок прежнего фото только в объекте запроса, без дополнительных запросов и состояния в общем ModelAdmin; невалидный POST добавления с настоящим JPEG и отсутствием новых файлов/записей/ошибок создания превью; валидную, но ещё не сохранённую форму; старую миниатюру после неуспешной замены без подмены нового файла в форме; невалидное редактирование без замены; отсутствие прежнего фото; успешное добавление и замену с новым превью и штатной очисткой старого оригинала и миниатюры. Используются существующий JPEG-помощник и изолированный `MEDIA_ROOT`, без рабочего media-каталога.

Модуль содержит тесты каталога, публичных форм и административной панели. Отдельные пятнадцать тестов управляемого содержимого находятся в `sitecontent/tests.py` и описаны в [документе приложения](../sitecontent/overview.md). ## `TagPageAndSitemapTests`

Шестнадцать тестов страницы тега, SEO-метаданных, хлебных крошек, навигации по категориям и sitemap проверяют:

- вывод только опубликованных изображений, счетчика, SEO-title, meta description и canonical;

- сохранение повторяемых параметров `color` в ссылках пагинации страницы тега;
- HTTP 200, `noindex,follow` и отдельное центрированное десктопное оформление карточки для существующего пустого тега, 404 для неизвестного slug;

- доступные визуальные цепочки и соответствующий валидный `BreadcrumbList` с абсолютными URL на страницах каталога, категории, тега, готовых работ, дизайнера и контактов; главная остаётся без крошек;
- сохранение визуальных крошек без JSON-LD на страницах с `noindex,follow`;
- отсутствие ORM-запросов при формировании метаданных крошек и безопасное экранирование динамического названия, способного преждевременно закрыть `<script>`.

## `CatalogSearchTests`

Четырнадцать тестов фиксируют поисковый контракт:

- NFKC-совместимую нормализацию, `casefold()`, эквивалентность `ё`/`е`, все поддерживаемые пробельные и знаковые разделители и распознавание одиночного числового номера;
- русские формы счетчика для значений 1, 2, 5, 11 и 21;
- удаление повторных слов с сохранением порядка и канонической строки, допуск одиночного однозначного номера, а также ошибки формы для пустого, пунктуационного, одно- или двухсимвольного текстового слова, более пяти уникальных слов, слишком большого числового номера или более 100 символов запроса;
- автоматическое обновление `normalized_tag` при обычном сохранении и `update_fields`, дружелюбное отклонение нормализованных дублей основных тегов и синонимов, нормализацию синонима, запрет многословного или пунктуационного синонима и совпадения с основным тегом;
- адрес формы и дополнительную доступную подсказку на странице категории: поиск отправляется на URL категории, её название показывается полужирным в русских кавычках и связывается с полем через `aria-describedby`, а общий каталог сохраняет глобальный URL без этой строки; CSS фиксирует одинаковое левое выравнивание подсказок, размер категорийной строки 14 px, верхний отступ 2 px и нижний отступ всего поискового блока 22 px;
- AND-семантику в пределах выбранной категории: `q` сохраняет категорию и исключает совпадения из других категорий, но отключает цвет и панели фильтров; точный синоним участвует в поиске, ссылки удаления слов и сброс последнего слова остаются в категории, превью результата показывает номер изображения, каталожная Fancybox-галерея не использует Hash-плагин истории, а неизвестный slug категории возвращает 404;
