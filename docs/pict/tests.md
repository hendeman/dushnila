# `skinali/pict/tests.py`

## Назначение

Стандартный модуль Django для тестов приложения `pict`.

## Текущее состояние

Модуль содержит 44 теста. Класс `PopularTagsByCategoryTests` проверяет формирование популярных тегов в каталоге и главную страницу:

- страница категории содержит только связанные с ней теги, включая встречающиеся у одного изображения;
- теги отсортированы по убыванию количества изображений;
- список ограничен десятью элементами;
- в HTML выводится название тега без значения счетчика;
- изображения каталога размечены отдельной Fancybox-группой `catalog-gallery`; модальный шаблон содержит `alt`, теги, номер, категории, внутренние стрелки и кнопки избранного/покупки, но не содержит счётчика;
- общий каталог сохраняет глобальный подсчет и такое же ограничение в десять тегов.
- первым пунктом категорий выводится «Все»: ссылкой внутри категории и выбранным элементом в общем каталоге.
- ссылки «Все» и категорий сохраняют выбранный GET-параметр `color`, но не добавляют его без активного цветового фильтра.
- без выбранного цвета выводится «Все цвета», а при выборе — белый круг-маркер, сохраненная серая обводка блока и ссылка «Сбросить цвет» с крестиком в независимой правой колонке;
- мобильная разметка содержит две кнопки фильтров, полноэкранные диалоги категорий и цветов, выбранные пункты с галочками и подключение `mobile-filters.js`;
- базовый шаблон содержит отдельные информационную панель и панель главного меню, два экземпляра PNG-логотипа, режим работы, телефонную ссылку, адаптивную кнопку меню, единый раскрывающийся список навигации, темный футер, полноширинный `site-main`, прозрачный контейнер `site-content`, версию `v=61` общего CSS со стилями овального меню категорий и пагинации, трехколоночную десктопную сетку, а также подключение `site-menu.js`; поисковая капсула находится только в шаблоне каталога;
- поисковая форма каталога содержит подсказку «Поиск, например море»;
- в разметке фиксированной модальной карточки каталога присутствует переключатель «Добавить в избранное»/«Удалить из избранного», шаблон подписи, fade-настройка Fancybox без штатной навигации, отключённый начальный zoom, отложенное проявление полностью подготовленного `contentEl` и блокировка запуска Panzoom из выделяемой текстовой области; мобильные стили задают естественную высоту подписи без внутреннего скролла, изображение высотой 78 px и уменьшенные элементы управления, а крестик размещён над карточкой; каталог также содержит контейнер превью `catalog-gallery`, пояснение `catalog-intro`, заголовок «Популярные запросы:» и отдельную угловую кнопку с активной и неактивной PNG-иконками;
- на публичной странице готовых работ отсутствует блок `site-search`.
- главная без поискового параметра содержит hero-баннер, полноширинные секции предложений, преимуществ и последних работ, три карточки предложений, шесть некликабельных карточек преимуществ, три последние кликабельные фотографии работ и квадратную ссылку на полную галерею; при поиске все четыре промоблока заменяются результатами. Тест создает четыре готовые работы и проверяет, что главная показывает только три новые в правильном порядке и размечает их общей Fancybox-галереей с именами без описаний.

Класс `PublicationTests` проверяет:

- включенный по умолчанию флаг `is_published` и подпись «Опубликовано» у `Pict` и `FinishedWork`;
- присутствие редактируемого чекбокса и фильтра публикации в обоих admin-классах;
- исключение неопубликованного `Pict` из общего каталога, категории с цветовым фильтром, страницы тега и поиска по номеру;
- исключение тега, связанного только с неопубликованным изображением, из популярных запросов.

Класс `ContactPageTests` проверяет публичную страницу «Связаться с нами»: тексты заголовков двух контактных панелей, обе телефонные и почтовые ссылки, изображение зоны обслуживания, её заголовок и пояснение о расстоянии до 75 км от Жодино.

Класс `ContactFormSubmissionTests` проверяет отдельный общий и телефонный уровни наследования форм, форму покупки на основе email-формы, ограничение email покупки в 50 символов, обязательный проверяемый `pict_id`, отклонение снятого с публикации изображения, ограничения остальных полей, honeypot `website`, последний пункт меню и три модальных окна, общий динамический шаблон четырёх форм, атомарное сохранение валидной AJAX-заявки вместе с Telegram-доставкой `pending`, связь покупки с `Pict`, неизменяемый снимок номера после удаления изображения, отсутствие записей для honeypot, слишком быстрой и невалидной отправки, JSON-ошибки с HTTP 422 и обычный POST с сохранением введённых значений. Admin-проверки фиксируют семь колонок общего списка с типом заявки после email, пользовательские и служебные поля карточек, полный read-only блок Telegram-доставки, канал/статус Telegram, кликабельную миниатюру покупки, сохранение `viewed_at` при первом просмотре и формирование имени собственной ссылкой, у которой светлый CSS-класс находится непосредственно на `<a>`.

Класс `ContactDeliveryTests` без реального сетевого доступа подменяет Telegram API и проверяет management-команду: успешное подтверждение и `message_id`, состав сообщения телефонной, email-заявки и покупки с номером изображения, отсутствие пустого телефона, временную ошибку с отложенным повтором, постоянную ошибку без автоматического повтора, восстановление зависшего `processing`, сохранение очереди при отсутствующих настройках, строгую передачу настроенного HTTP(S)-прокси при отключенном чтении системных прокси, отсутствие отдельной таблицы доставок в admin и перенос действия повтора в список заявок.

Класс `DesignerPageTests` проверяет страницу «Услуги дизайнера»: основные информационные разделы, выделенную ссылку «Напишите нам» в порядке покупки по номеру изображения, карточку стоимости `30 BYN`, баннер эксклюзивной разработки с иллюстрацией, CTA «Обсудить идею», условия бесплатного предоставления каталожных изображений и три ссылки на страницу контактов.

Класс `SessionFavoritesTests` проверяет:

- добавление и повторное удаление изображения из сессии;
- независимость избранного у двух браузерных сессий;
- вывод недавно добавленных элементов первыми, номера, описания и общей с каталогом Fancybox-разметки `catalog-gallery` без угловой иконки превью;
- скрытие пустого пункта «Избранное», его показ последним пунктом после добавления, единый темный счетчик адаптивного меню, активную угловую иконку каталога и кнопку в галерее;
- повторное использование в «Избранном» шаблона каталожной подписи с кнопкой удаления;
- запрет GET для переключателя и ответ 404 для несуществующего или снятого с публикации изображения;
- автоматическое удаление снятого с публикации изображения из сохраненного списка и счетчика избранного.

Класс `FinishedWorkTests` проверяет:

- обратную связь `Pict.finished_works`, получение категорий через связанное изображение и сохранение готовой работы после удаления `Pict` с обнулением ссылки;
- публичный маршрут, пункт меню, квадратные карточки с шестиколоночной широкой сеткой и двумя колонками до 900 px, а также Fancybox-разметку с именем и номером изображения без описания и категории в подписи;
- отсутствие номера и поля категории в подписи после потери необязательной связи;
- сортировку по новизне, пагинацию по 6 работ, класс `catalog-pagination` и обозначение текущей страницы через `aria-current`.
- общий с каталогом список категорий, фильтрацию через `?category=<slug>`, исключение работ другой категории и работ без каталожной связи, сохранение категории при переходе между страницами, мобильный диалог и 404 для неизвестного slug.
- исключение снятой с публикации работы из полной галереи и блока последних работ на главной;
- уменьшенные размеры миниатюр готовой работы в admin, условное появление галереи связанных работ в форме изображения и подключение общего модального просмотрщика исходных файлов.

Тестовые изображения каталога и готовых работ создаются как ORM-записи со строковыми путями к файлам; реальные файлы для этих проверок не нужны.

## Рекомендуемые области покрытия

- Модели: URL, строковые представления, связи и автоматический номер `Pict`.
- Views: поиск по номеру/тегу, пустой и короткий запрос, фильтры цвета/тега, пагинация, неверные slug.
- URL: reverse/resolve для обоих маршрутов с именем `skinali` и маршрута `designer` без завершающего `/`.
- Admin/form: создание первой записи и вычисление следующего `name`.
