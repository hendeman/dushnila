# `skinali/pict/services/contact_delivery.py`

## Назначение

Реализует доставку сохраненных контактных заявок в Telegram без Redis, Celery и фоновых потоков web-процесса. SQLite используется как небольшая устойчивая очередь, а сервис обрабатывает ограниченную пачку по вызову management-команды.

## Telegram-клиент

- `get_telegram_configuration()` проверяет `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, положительные тайм-ауты и необязательный `TELEGRAM_PROXY_URL` до изменения очереди. Прокси допускается только со схемой `http` или `https`, именем хоста и явным портом.
- `format_contact_request_message()` формирует обычный текст: ID и тип заявки, имя, только заполненные телефон/email, необязательные вопрос/комментарий, номер изображения для заявки покупки и время создания. `parse_mode` не используется, поэтому пользовательский текст не интерпретируется как HTML или Markdown.
- `send_telegram_message()` вызывает официальный `sendMessage` через отдельную `requests.Session` с раздельными connect/read timeout. У сессии отключен `trust_env`, поэтому системные `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` не влияют на маршрут Telegram-запроса.
- Пустой `TELEGRAM_PROXY_URL` означает прямое подключение. При заполненном значении один и тот же HTTP(S)-прокси передается для адресов `http` и `https`; при его сбое запрос не повторяется напрямую, а доставка переходит в обычный график повторов.
- Успехом считается JSON с `ok=true` и целочисленным `result.message_id`. Один HTTP 200 без этих данных не подтверждает доставку.
- Ошибки `429`, `5xx`, тайм-ауты и сетевые сбои считаются временными. Остальные явные ошибки Bot API считаются постоянными. Если Telegram прислал `parameters.retry_after`, это время имеет приоритет над локальным расписанием.
- URL запроса содержит токен, поэтому строки исключений `requests` намеренно не сохраняются и не выводятся в журнал.

## Обработка очереди

`process_pending_telegram_deliveries()`:

1. Проверяет конфигурацию.
2. Возвращает зависшие `processing` старше 10 минут в `retry`; исчерпавшие лимит получают `failed`.
3. Выбирает до 20 готовых `pending`/`retry`.
4. Для каждой записи выполняет условный атомарный `UPDATE`: ставит `processing`, фиксирует начало и увеличивает число попыток. Если другой процесс уже забрал строку, обновление ничего не меняет.
5. Завершает запись в SQLite и выполняет HTTPS-запрос без открытой транзакции.
6. Сохраняет `sent`, время и `message_id` либо назначает повтор через 1, 5, 15 и затем 60 минут.
7. После пяти попыток или постоянной ошибки устанавливает `failed`.

Параметры пачки, числа попыток и времени восстановления можно переопределить аргументами management-команды. Отдельные короткие `UPDATE` уменьшают конкуренцию записи SQLite.

## Гарантии и ограничения

- Заявка уже сохранена до начала внешней отправки, поэтому сбой Telegram не приводит к потере контактов.
- Семантика доставки — как минимум один раз. Если Telegram принял сообщение, но сетевое соединение оборвалось до получения ответа, повтор может создать дубликат. ID заявки внутри текста позволяет распознать такой случай; Bot API `sendMessage` не предоставляет пользовательский ключ идемпотентности.
- Токен, chat ID и прокси берутся только из настроек окружения. Корневой `.env` загружается в `settings.py`, причем системное окружение имеет приоритет.
- Канал email зарезервирован моделью, но сервис его пока не обрабатывает.
