# `skinali/pict/models.py`

## Назначение

Определяет доменные модели каталога, готовых работ, контактных заявок и связи между ними.

## Схема связей

```text
Category  *───*  Pict  *───*  Color
                    |
                    ├───*───*  TagPict
                    |
                    1
                    |
                    *
              FinishedWork

ContactRequest  1───*  ContactRequestDelivery
```

Все три классификатора связаны с изображением отношением многие-ко-многим. `FinishedWork` связан с `Pict` отношением многие-к-одному: одна работа использует не более одного изображения каталога, а изображение может использоваться в нескольких работах. `ContactRequest` не связан с каталогом и хранит прошедшие проверку заявки посетителей. Одна заявка может иметь отдельную доставку для каждого внешнего канала.

## `Color`

| Поле | Тип | Ограничения |
|---|---|---|
| `color` | `CharField(100)` | отображаемое название |
| `slug_color` | `SlugField(100)` | уникальный, индексированный |

`__str__()` возвращает `color`. В admin модель отображается как «Цвет»/«Цвета». Собственного `get_absolute_url()` нет.

## `TagPict`

| Поле | Тип | Ограничения |
|---|---|---|
| `tag` | `CharField(100)` | индексированный текст ключевого слова |
| `slug` | `SlugField(100)` | уникальный, индексированный |

- `__str__()` возвращает `tag`.
- `get_absolute_url()` строит именованный URL `tag` с `tag_slug=self.slug`.
- Обратное имя связи от тега к изображениям — `tags` из-за `Pict.tags.related_name`.

## `Category`

| Поле | Тип | Ограничения |
|---|---|---|
| `cat` | `CharField(100)` | отображаемое название |
| `slug` | `SlugField(100)` | уникальный, индексированный |

- `__str__()` возвращает `cat`.
- `get_absolute_url()` строит именованный URL `skinali` с `slug_cat=self.slug`.
- Явный `related_name` у связи `Pict.cat` не задан, поэтому обратный manager — `pict_set`.

## `Pict`

| Поле | Тип | Ограничения и смысл |
|---|---|---|
| `name` | `IntegerField` | уникальный, индексированный номер/имя файла |
| `alt` | `CharField(250)` | необязательное описание (`blank=True`) |
| `photo` | `ImageField` | загрузка в `photos/` внутри `MEDIA_ROOT` |
| `time_update` | `DateTimeField` | `auto_now_add=True`; фактически время создания, несмотря на имя |
| `cat` | `ManyToManyField(Category)` | обязательная на уровне формы связь категорий |
| `tags` | `ManyToManyField(TagPict)` | необязательная, `related_name='tags'` |
| `color` | `ManyToManyField(Color)` | обязательная на уровне формы связь цветов |

- `__str__()` возвращает строковое представление `name`.
- `Meta.ordering = ['-id']`: новые записи идут первыми.
- `__add__(other)` возвращает `int(Pict.objects.first().name) + other`; метод используется формой admin для предложения следующего номера.

## `FinishedWork`

| Поле | Тип | Ограничения и смысл |
|---|---|---|
| `name` | `CharField(200)` | обязательное имя работы; уникальность не требуется |
| `description` | `TextField` | необязательное описание (`blank=True`) |
| `photo` | `ImageField` | единственная фотография работы; загрузка в `finished_works/` внутри `MEDIA_ROOT` |
| `catalog_image` | `ForeignKey(Pict)` | необязательная связь с изображением каталога; `null=True`, `blank=True`, `SET_NULL`, `related_name='finished_works'` |
| `created_at` | `DateTimeField` | дата и время создания (`auto_now_add=True`) |

- `__str__()` возвращает имя и номер связанного изображения; без связи — только имя.
- `Meta.ordering = ['-created_at', '-id']`: новые работы выводятся первыми.
- Категория отдельно не хранится. Если выбрано `catalog_image`, категории готовой работы берутся из `catalog_image.cat`; без связи с каталогом категорий у работы нет.
- При удалении `Pict` готовая работа сохраняется, а `catalog_image` автоматически становится `NULL`.
- Обратная связь от `Pict` доступна как `pict.finished_works`.

## `ContactRequest`

| Поле | Тип | Ограничения и смысл |
|---|---|---|
| `request_type` | `CharField(20)` | тип формы из `TextChoices`: `callback` («Обратный звонок») или `question` («Вопрос») |
| `name` | `CharField(20)` | проверенное имя посетителя |
| `phone` | `CharField(20)` | проверенный телефон в исходном форматировании |
| `question` | `CharField(250)` | необязательный вопрос (`blank=True`) |
| `created_at` | `DateTimeField` | время сохранения (`auto_now_add=True`) |

- `__str__()` возвращает имя и телефон.
- `Meta.ordering = ['-created_at', '-id']`: новые заявки находятся первыми.
- Модель хранит только валидные заявки, прошедшие антиспам-проверки обработчика. Honeypot и подозрительно быстрые отправки внешне получают успешный ответ, но запись не создают.
- Состояние отправки не смешивается с состоянием самой заявки и хранится в `ContactRequestDelivery`.

## `ContactRequestDelivery`

| Поле | Тип | Ограничения и смысл |
|---|---|---|
| `contact_request` | `ForeignKey(ContactRequest)` | обязательная заявка; `CASCADE`, `related_name='deliveries'` |
| `channel` | `CharField(20)` | `telegram` или зарезервированный для будущего `email` |
| `status` | `CharField(20)` | `pending`, `processing`, `retry`, `sent` или `failed`; индексируется |
| `attempts` | `PositiveSmallIntegerField` | количество фактически начатых сетевых попыток |
| `next_attempt_at` | `DateTimeField` | время готовности к первой или повторной попытке; индексируется, после завершения `NULL` |
| `processing_started_at` | `DateTimeField` | позволяет восстановить задачу после аварийной остановки обработчика |
| `sent_at` | `DateTimeField` | время подтвержденной отправки |
| `external_message_id` | `BigIntegerField` | `message_id`, возвращенный Telegram |
| `last_error` | `TextField` | безопасное диагностическое сообщение без токена бота |
| `created_at`, `updated_at` | `DateTimeField` | время создания и последнего изменения состояния |

- Уникальное ограничение на `(contact_request, channel)` предотвращает две очереди одного канала для одной заявки.
- Составной индекс `(channel, status, next_attempt_at)` обслуживает выборку готовой пачки.
- Удаление заявки каскадно удаляет ее служебные доставки.
- Модель отделена от `ContactRequest`, поэтому будущая email-доставка сможет иметь собственный независимый статус и число попыток.

## Использование моделями-потребителями

- [views.py](views.md) фильтрует `Pict` по `name`, `tags__tag`, `tags__slug`, `cat__slug` и `color__slug_color`.
- [admin.py](admin.md) показывает категории, цвета и превью изображения.
- [views.py](views.md) загружает `FinishedWork` вместе со связанным `Pict` и его категориями для публичной галереи.
- [admin.py](admin.md) позволяет связать готовую работу с изображением каталога через поиск по номеру.
- [forms.py](forms.md) вычисляет начальное значение `name` через перегруженный `Pict.__add__()`.
- [urls.py](urls.md) использует имена URL, на которые ссылаются `get_absolute_url()`.
- [views.py](views.md) создает `ContactRequest` после успешной серверной валидации контактной формы.
- [admin.py](admin.md) предоставляет список, фильтры и поиск по контактным заявкам.
- [services.py](services.md) атомарно забирает готовые `ContactRequestDelivery` и обновляет результат Telegram.

## Особенности и риски

- `__add__()` зависит от наличия хотя бы одной записи. На пустой таблице `Pict.objects.first()` вернет `None` и обращение к `.name` завершится ошибкой.
- Из-за сортировки `-id` `first()` означает последнюю добавленную запись, а не гарантированно максимальное значение `name`.
- Метод `__add__()` выполняет запрос к БД и использует необычную для модели семантику оператора `+`.
- Для обязательности ManyToMany нет ограничения на уровне БД: она обеспечивается формами/интерфейсом.
- `time_update` не обновляется при редактировании.
- Изменение категорий у связанного `Pict` сразу меняет категории готовой работы, поскольку отдельной копии категорий у `FinishedWork` нет.
