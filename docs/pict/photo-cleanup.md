# Очистка фотографий каталога и готовых работ

## Назначение и состав

`pict/services/photo_cleanup.py` содержит общий механизм очистки оригиналов и связанных миниатюр `sorl-thumbnail`. Его используют сигналы моделей `Pict` и `FinishedWork`, admin-переименование и команда `cleanup_unused_photos`. Новые таблицы, зависимости, постоянные worker-процессы и публичные маршруты не нужны.

## Автоматическая очистка

- `pre_save` запоминает прежнее значение `photo` из БД; `post_save` сравнивает его с фактически сохранённым путём. Создание записи, неизменённый файл и `save(update_fields=...)` без `photo` не запускают очистку.
- Замена или очистка `photo`, удаление объекта и массовое удаление через queryset назначают удаление старого оригинала через `transaction.on_commit(using=...)`. Откат внешней транзакции отменяет callback; старый файл и его миниатюры остаются доступны.
- Непосредственно перед очисткой проверяются все `FileField`/`ImageField` управляемых зарегистрированных моделей в той же БД через `_base_manager`, включая неопубликованные записи и изображения квиза. Если любой объект ссылается на тот же путь, файл и его миниатюры сохраняются. Совпадающий путь в другом storage тоже консервативно считается ссылкой.
- Сначала штатный API `sorl-thumbnail` удаляет связанные кешированные миниатюры и их KV-записи, затем Django storage удаляет оригинал. При отсутствии оригинала очистка миниатюр всё равно выполняется.
- Ошибка БД, storage или очистки миниатюр журналируется и не отменяет уже сохранённую запись. Если очистка миниатюр не удалась, оригинал оставляется для повторной попытки служебной командой. При повторном запуске отсутствующий файл безопасно пропускается.
- Действия admin «Переименовать файлы…» используют этот же поток после сохранения нового пути; прямое удаление прежнего оригинала из admin исключено. Незавершённая копия после ошибки переименования очищается общим сервисом с проверкой ссылок.

Очистка ограничена оригиналами внутри `photos/` и `finished_works/`. Абсолютные пути, `..`, обратные разделители, пустые компоненты и пути вне этих папок отвергаются. Для файлового storage проверяется разрешённая абсолютная граница; символические ссылки и переходы за пределы папок не обходятся. Корень media при этом может находиться по настроенному `DJANGO_MEDIA_ROOT`.

Изменение описания, имени, публикации или связи работы с каталогом само по себе файл не удаляет. Удаление `Pict` не удаляет отдельную фотографию связанной готовой работы.

## Поиск накопившихся неиспользуемых файлов

Из директории с `manage.py`:

```console
python manage.py cleanup_unused_photos
python manage.py cleanup_unused_photos --dry-run
```

Обе команды только выводят отчёт: выбранные папки, пути, размеры и суммарный объём найденных оригиналов. БД и файлы не изменяются. Без `--table` просматриваются обе папки оригиналов, включая вложенные директории; другие media-папки и общий кеш миниатюр не сканируются и не очищаются вслепую.

Перед удалением следует проверить отчёт и сделать резервную копию media и соответствующей БД:

```console
python manage.py cleanup_unused_photos --delete
```

Параметры:

- `--table images` — только «Изображения», папка `photos/`; `--table finished-works` — только «Готовые работы», папка `finished_works/`. Без параметра или с `--table all` обрабатываются обе папки. Выбор одинаково действует в отчёте и при удалении; неизвестное значение отвергается до обхода файлов. Соответствие таблиц папкам хранится в общем `PHOTO_TABLE_DIRECTORIES`.
- `--delete` — явно разрешает необратимое удаление найденных оригиналов и их связанных миниатюр; несовместим с `--dry-run`.
- `--min-age-hours 24` — минимальный возраст неиспользуемого файла по времени изменения, по умолчанию сутки, целое число не менее 1. Свежие файлы пропускаются, чтобы не затронуть обычную незавершённую загрузку.
- `--database default` — БД, в которой проверяются ссылки; storage берётся из настроенного `default`.

```console
python manage.py cleanup_unused_photos --table images --dry-run
python manage.py cleanup_unused_photos --table finished-works --dry-run
python manage.py cleanup_unused_photos --table finished-works --delete
```

Выбор таблицы ограничивает только папки поиска, но не проверку использования: ссылки из всех файловых полей БД, включая другую таблицу и квиз, продолжают защищать оригинал и миниатюры от удаления. Неиспользуемый файл уже не имеет записи, поэтому его принадлежность определяется папкой загрузки, а не строкой в таблице.

Список используемых путей загружается один раз, обход файлов выполняется последовательно. В режиме удаления ссылки и возраст повторно проверяются непосредственно перед каждой очисткой. Итог отдельно показывает кандидатов, объём оригиналов (без размера миниатюр), удалённые файлы, пропуски при перепроверке, свежие файлы и ошибки. При ошибках команда возвращает ненулевой код завершения; уже обработанные файлы не восстанавливаются. Команда не требует дополнительной серверной памяти для содержимого изображений и не открывает их для декодирования.

## Ограничения

Файловое хранилище не участвует в транзакции БД: новая загрузка после отката сохранения может остаться на диске. Служебная команда предназначена в том числе для таких файлов и для повторной очистки после ошибок. `QuerySet.update()`, `bulk_update()` и прямой SQL не вызывают сигналы; оставленные ими оригиналы также находятся командой.

Под «используется» понимается сохранённый путь в файловом поле БД. Ручные прямые ссылки на media в HTML/JS, сторонние сайты и резервные копии не анализируются. Исторические записи с нестандартными/вручную изменёнными путями необходимо проверить перед массовой очисткой. При ручном присвоении существующих путей, импорте или длительной транзакции, превышающей защитный возраст, массовую очистку лучше запускать вне такого процесса. Не следует использовать другую БД, если тот же media-каталог обслуживает основную БД.

Отдельные потерянные файлы общего кеша, для которых `sorl-thumbnail` уже не хранит связь с оригиналом, эта команда не удаляет. Освобождённый URL оригинала перестаёт работать; автоперезапись одноимённых файлов не включена, стандартная защита storage от коллизий сохранена.

## Тесты

`pict/test_photo_cleanup.py` изолирует media во временных каталогах и проверяет замену/удаление обеих моделей, очистку миниатюр, отложенное выполнение, откат транзакций, общие и неопубликованные ссылки, ссылки из другого приложения, неизменённые и частичные сохранения, повторные замены, отсутствующие оригиналы, ошибки и безопасные границы путей. Отдельный `TransactionTestCase` проверяет настоящий commit без ручного запуска callback, rollback admin-переименования и ошибку storage после commit. Команда проверяется в режимах отчёта/удаления, с защитой свежих файлов, повторной проверкой ссылок и возраста, вложенными папками и неверными аргументами. Выбор каждой таблицы ограничивает отчёт и удаление её папкой, другая папка даже не сканируется; `all` совпадает с режимом по умолчанию, межтабличные ссылки сохраняются, недопустимые таблицы и корни обхода отвергаются. Проверка реальной символической ссылки пропускается там, где ОС не разрешает её создание; проверка изменённого разрешённого пути (включая внутренние junction) не требует прав ОС.
