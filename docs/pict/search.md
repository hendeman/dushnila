# `skinali/pict/search.py`

## Назначение

Содержит общие правила нормализации и разбора поискового запроса, построение ORM-поиска по каталогу и русскую подпись количества результатов. Модуль не обрабатывает HTTP сам: форму проверяет [forms.py](forms.md), а [views.py](views.md) применяет подготовленный запрос к опубликованным изображениям.

## Константы

| Константа | Значение | Назначение |
|---|---:|---|
| `SEARCH_QUERY_PARAMETER` | `q` | имя GET-параметра |
| `SEARCH_QUERY_MAX_LENGTH` | `100` | максимальная длина исходной строки, проверяемая формой |
| `SEARCH_TERMS_LIMIT` | `5` | максимум уникальных поисковых слов |
| `SEARCH_TERM_MIN_LENGTH` | `3` | минимальная длина каждого слова, кроме одиночного числового номера |
| `SEARCH_IMAGE_NUMBER_MAX` | `2147483647` | максимальный номер, совместимый с положительным 32-битным `IntegerField` |

## Нормализация и разбор

`normalize_search_value(value)` последовательно:

1. применяет Unicode-нормализацию NFKC;
2. выполняет `casefold()`;
3. заменяет `ё` на `е`;
4. считает разделителями любые пробельные символы, запятую, двоеточие, точку с запятой, `#`, дефис `-`, короткое тире `–` и длинное тире `—`;
5. заменяет последовательность разделителей одним пробелом и удаляет внешние пробелы.

`parse_search_query(value)` разбивает нормализованную строку на слова, удаляет повторы и сохраняет порядок первого появления. Результат возвращается как неизменяемый `ParsedSearchQuery` с полями:

- `normalized` — каноническая строка из уникальных слов, соединенных одиночными пробелами;
- `terms` — кортеж уникальных слов в исходном порядке;
- `image_number` — целое число, только если запрос после разбора состоит из одного цифрового слова; иначе `None`.

Например, `#МОРЕ, море; ЗАКАТ` дает слова `('море', 'закат')`, а `#123` считается поиском номера `123`.

Ограничения длины, числа, максимального номера и минимального размера слов проверяет `CatalogSearchForm`, а не этот модуль. Каждое текстовое слово должно содержать не менее трех символов и хотя бы одну букву или цифру; поэтому одно- и двухсимвольные слова, строка только из разделителей либо иной пунктуации отклоняются формой. Исключение действует только для запроса из одного числового слова: даже однозначный номер изображения допустим.

## Построение запроса к каталогу

`apply_catalog_search(queryset, parsed_query)` принимает уже подготовленный queryset опубликованного каталога.

- Одиночное цифровое значение фильтруется точным условием по `Pict.name`.
- Текстовые слова объединяются по правилу AND: каждое слово должно найтись хотя бы в одном теге изображения.
- Основной тег сопоставляется через `TagPict.normalized_tag__contains`.
- Поисковый синоним сопоставляется только точным равенством `TagAlias.normalized_alias`.
- Описание `Pict.alt`, категории и цвета в поиске не участвуют.

Для каждого слова добавляется коррелированное условие `Exists` к промежуточной M2M-таблице `Pict.tags`. Поэтому совпадения нескольких тегов или синонимов не размножают строки изображений и не требуют `distinct()`.

## Релевантность и сортировка

Каждое слово добавляет результату балл:

| Совпадение | Балл |
|---|---:|
| точное совпадение основного нормализованного тега | 3 |
| точное совпадение нормализованного синонима | 2 |
| частичное вхождение в основной нормализованный тег | 1 |

Баллы всех слов суммируются. Итоговая сортировка: сначала `-search_relevance`, затем `-id`, поэтому при одинаковой релевантности новые изображения находятся выше.

Все слова компилируются в один SQL-запрос списка. Увеличение числа слов до пяти добавляет условия `EXISTS` и усложняет этот SQL, но не создает отдельный запрос к БД на каждое слово. Проверяемый контракт именно ORM-выборки 30 каталожных записей состоит из четырех запросов: `COUNT`, выборка `Pict`, prefetch тегов и prefetch категорий. Это число не описывает полный HTTP-рендер с контекстом, интеграциями и обращениями кеша миниатюр.

## Подпись количества

`format_image_count(count)` возвращает русскую форму строки `Найдено N изображение/изображения/изображений` с учетом исключений 11–14.

## Связанные уровни

- [forms.py](forms.md) проверяет `q` и сохраняет разобранный объект в `CatalogSearchForm.parsed_query`.
- [models.py](models.md) автоматически поддерживает нормализованные значения основных тегов и синонимов.
- [views.py](views.md) включает глобальный режим поиска на обоих URL каталога, формирует пагинацию и ссылки удаления слов.
- [admin.py](admin.md) позволяет редактировать синонимы внутри основного тега.
- [migrations/README.md](../migrations/README.md) описывает безопасное заполнение нормализованных значений существующих тегов.

## Особенности и риски

- Обычный B-tree индекс уникального `normalized_tag` не ускоряет в SQLite поиск вида `LIKE '%слово%'`; индекс `normalized_alias` применим к точному сопоставлению синонима.
- Число SQL-запросов не зависит от числа слов, но стоимость единственного SQL растет с каждым дополнительным `Exists`.
- И `ParsedSearchQuery.terms`, и собранная из них строка `normalized` не содержат повторов; эта каноническая строка сохраняется в ссылках пагинации.

## Когда читать исходник

При изменении допустимых разделителей, нормализации, лимитов, логики AND, источников совпадений, ранжирования или ORM-структуры поиска.
