# `skinali/pict/search.py`

## Назначение

Содержит общие правила нормализации и разбора поискового запроса, построение ORM-поиска по каталогу и русскую подпись количества результатов. Модуль не обрабатывает HTTP сам: форму проверяет [forms.py](forms.md), а [views.py](views.md) применяет подготовленный запрос к опубликованным изображениям.

## Константы

| Константа | Значение | Назначение |
|---|---:|---|
| `SEARCH_QUERY_PARAMETER` | `q` | имя GET-параметра |
| `SEARCH_QUERY_MAX_LENGTH` | `100` | максимальная длина исходной строки, проверяемая формой |
| `SEARCH_TERMS_LIMIT` | `5` | максимум уникальных поисковых слов |
| `SEARCH_TERM_MIN_LENGTH` | `3` | минимальная длина каждого слова, кроме одиночного числового номера |
| `SEARCH_IMAGE_NUMBER_MAX` | `2147483647` | максимальный номер, совместимый с положительным 32-битным `IntegerField` |

## Нормализация и разбор

`normalize_search_value(value)` последовательно:

1. применяет Unicode-нормализацию NFKC;
2. выполняет `casefold()`;
3. заменяет `ё` на `е`;
4. считает разделителями любые пробельные символы, запятую, двоеточие, точку с запятой, `#`, дефис `-`, короткое тире `–` и длинное тире `—`;
5. заменяет последовательность разделителей одним пробелом и удаляет внешние пробелы.

`parse_search_query(value)` разбивает нормализованную строку на слова, удаляет повторы и сохраняет порядок первого появления. Результат возвращается как неизменяемый `ParsedSearchQuery` с полями:

- `normalized` — каноническая строка из уникальных слов, соединенных одиночными пробелами;
- `terms` — кортеж уникальных слов в исходном порядке;
- `image_number` — целое число, только если запрос после разбора состоит из одного цифрового слова; иначе `None`.

Например, `#МОРЕ, море; ЗАКАТ` дает слова `('море', 'закат')`, а `#123` считается поиском номера `123`.

Ограничения длины, числа, максимального номера и минимального размера слов проверяет `CatalogSearchForm`, а не этот модуль. Каждое текстовое слово должно содержать не менее трех символов и хотя бы одну букву или цифру; поэтому одно- и двухсимвольные слова, строка только из разделителей либо иной пунктуации отклоняются формой. Исключение действует только для запроса из одного числового слова: даже однозначный номер изображения допустим.

## Лемматизация

`lemmatize_search_term(term)` применяет `pymorphy3` к нормализованному слову из русских букв и выбирает только первый, наиболее вероятный разбор. Лемма повторно нормализуется, включая `ё` → `е`. Числа, латиница и смешанные буквенно-цифровые значения сохраняются буквально. `get_search_lemmas(value)` получает уникальные леммы каждого слова многословного тега.

Русский `MorphAnalyzer` загружается лениво один раз на процесс; первый параллельный вызов защищён блокировкой. LRU-кеш ограничен 2048 словами. Нормализация и валидация формы не загружают словарь. Поиск одиночного числового номера также обходится без анализатора.

Леммы тегов и синонимов заранее записываются в `TagSearchLemma`; при поиске анализируются только слова проверенного запроса. Сохранение исходного значения и его индекса атомарно. Существующие строки заполняет миграция `0038`; после обновления словаря или bulk-операций индекс перестраивается командой `rebuild_search_lemmas`. Версии анализатора и словаря закреплены в обоих корневых requirements.

## Построение запроса к каталогу

`apply_catalog_search(queryset, parsed_query, use_lemmatization=True)` принимает уже подготовленный queryset опубликованного каталога и выбранный режим. Представление общего каталога передаёт всю опубликованную выборку, а представление выбранной категории предварительно ограничивает её этой категорией; цветовой фильтр в режиме поиска не применяется.

Глобальная системная карточка `sitecontent.CatalogSearchSettings` находится в «Управлении сайтом → Настройки сайта»; из списка «Ключевые слова» суперпользователь может перейти по ссылке «Настройки сайта». Флаг «Учитывать словоформы при поиске» включён по умолчанию. Перед каждым валидным текстовым поиском представление одним коротким запросом читает актуальный флаг из БД без межзапросного кеша, поэтому изменение действует со следующего запроса во всех процессах. Номер изображения, невалидная форма и каталог без `q` не читают настройку. Если системная строка отсутствует, действует включённый режим.

- Одиночное цифровое значение фильтруется точным условием по `Pict.name`.
- Текстовые слова объединяются по правилу AND: каждое слово должно найтись хотя бы в одном теге изображения.
- Основной тег сопоставляется точным равенством `TagPict.normalized_tag` либо равенством сохранённой леммы одного из его слов лемме запроса.
- Поисковый синоним сопоставляется точным равенством `TagAlias.normalized_alias` либо равенством его сохранённой леммы лемме запроса.
- Во включённом режиме частичные вхождения отключены: `автомоб` не находит `автомобиль`, а `автомобилями` находит его по лемме. `море` находит слово в многословном теге `красное море`.
- В выключенном режиме библиотека и индекс лемм при поиске не вызываются. Поиск возвращается к частичному вхождению `normalized_tag__contains`, расширенному также на `normalized_alias__contains`: фрагмент может найти и основной тег, и его синоним. Леммы продолжают обновляться при сохранении владельцев, поэтому включение не требует перестроения. Уже загруженный анализатор не выгружается из памяти при смене режима.
- Описание `Pict.alt`, категории и цвета в поиске не участвуют.

Для каждого слова альтернативные способы совпадения объединяются через OR коррелированных `Exists` к промежуточной M2M-таблице `Pict.tags`. Слова по-прежнему объединяются через AND. Совпадения нескольких тегов, синонимов или лемм не размножают строки изображений и не требуют `distinct()`; все способы совпадения входят в один SQL списка, без повторного поиска при отсутствии точного результата.

## Релевантность и сортировка

Каждое слово добавляет результату балл:

| Совпадение | Балл |
|---|---:|
| точное совпадение основного нормализованного тега | 4 |
| точное совпадение нормализованного синонима | 3 |
| совпадение леммы основного тега или синонима | 2 |

Таблица выше описывает включённый режим. В выключенном режиме сохраняются прежние веса: точный основной тег — 3, точный синоним — 2, частичное вхождение в тег или синоним — 1. Баллы всех слов суммируются. Итоговая сортировка: сначала `-search_relevance`, затем `-id`, поэтому при одинаковой релевантности новые изображения находятся выше.

Все слова компилируются в один SQL-запрос списка. Увеличение числа слов до пяти добавляет условия `EXISTS` и усложняет этот SQL, но не создает отдельный запрос к БД на каждое слово. После подготовки queryset ORM-выборка 30 каталожных записей состоит из четырёх запросов: `COUNT`, выборка `Pict`, prefetch тегов и prefetch категорий. Перед подготовкой текстового поиска выполняется ещё один запрос режима; `get_queryset().count()` содержит два SQL независимо от числа слов. Эти числа не описывают полный HTTP-рендер с контекстом, интеграциями и обращениями кеша миниатюр.

## Подпись количества

`format_image_count(count)` возвращает русскую форму строки `Найдено N изображение/изображения/изображений` с учетом исключений 11–14.

## Связанные уровни

- [forms.py](forms.md) проверяет `q` и сохраняет разобранный объект в `CatalogSearchForm.parsed_query`.
- [models.py](models.md) автоматически поддерживает нормализованные значения основных тегов и синонимов.
- [views.py](views.md) выполняет поиск по всему каталогу на корневом URL и в пределах выбранной категории на её URL, формирует пагинацию и сохраняющие область поиска ссылки удаления слов.
- [admin.py](admin.md) позволяет редактировать синонимы внутри основного тега.
- [migrations/README.md](../migrations/README.md) описывает безопасное заполнение нормализованных значений существующих тегов.

## Особенности и риски

- Во включённом режиме точные значения и леммы сравниваются через индексируемое равенство. Для лемм есть индекс `lemma` и уникальные составные индексы владельца/леммы. Выключенный режим использует `LIKE '%слово%'`, который обычный B-tree индекс не ускоряет.
- Анализатор не исправляет опечатки и не выбирает значение слова по контексту: используется наиболее вероятный разбор, поэтому альтернативная лемма неоднозначного слова может не найтись. Разные теги могут иметь одинаковую лемму: уникальность исходных нормализованных значений не переносится на леммы разных владельцев.
- Число SQL-запросов не зависит от числа слов, но стоимость единственного SQL растет с каждым дополнительным `Exists`.
- И `ParsedSearchQuery.terms`, и собранная из них строка `normalized` не содержат повторов; эта каноническая строка сохраняется в ссылках пагинации.

## Когда читать исходник

При изменении допустимых разделителей, нормализации, лимитов, логики AND, источников совпадений, ранжирования или ORM-структуры поиска.

## Локальный замер 12 октября 2026 года

Windows, Python 3.11, `pymorphy3 2.0.6` с закреплённым русским словарём; отдельный процесс после `django.setup()`. Локальная БД содержит 54 изображения, 19 тегов, один синоним и 20 строк индекса после миграции. Разбор пяти слов `автомобилями красными розами деревьями морями` проверен 200 раз; перед каждым измерением без кеша очищался только кеш слов, сам анализатор переиспользовался.

| Измерение | Результат |
|---|---:|
| Первый вызов с импортом анализатора и загрузкой словаря | 60,56 мс |
| Пять слов без кеша, медиана / p95 | 0,266 / 0,332 мс |
| Пять слов с кешем, медиана / p95 | 0,0038 / 0,0043 мс |
| Дополнительный working set / private memory при первой загрузке | 20,56 / 20,71 МиБ |
| ORM: создание запроса, COUNT и получение страницы, одно слово, медиана / p95 | 3,43 / 4,54 мс |
| ORM: то же для пяти слов, медиана / p95 | 13,17 / 14,66 мс |

ORM проверен 50 раз для `морями` и `морями лесами закатами цветами деревьями`, с prefetch тегов и категорий. Это не полный HTTP-рендер и не нагрузочный замер production: фактические результаты поиска и небольшой объём локальной БД влияют на стоимость SQL. Показатели памяти относятся к одному Windows-процессу и загрузке словаря, без насыщения LRU-кеша. Перед развёртыванием или увеличением числа Passenger-процессов нужен отдельный замер на Hostland; параметры сервера этими числами не подтверждаются.
