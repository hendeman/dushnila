# Интеграции публичного сайта

## Управление

Суперпользователю в Django Admin доступен пункт «Интеграции» в разделе «Управление сайтом» по адресу `/<DJANGO_ADMIN_PATH>/sitecontent/integration/`. Штатные хлебные крошки списка, карточек и журнала ведут в «Управление сайтом». Каждая запись объединяет название, описание, флаг включения, порядок, список страниц и поля HTML/JavaScript перед `</head>`, сразу после `<body>` и перед `</body>`. Новые записи выключены по умолчанию. При одинаковом порядке первой подключается запись с меньшим ID.

Прежние маршруты `/<DJANGO_ADMIN_PATH>/pict/integration/` и `/<DJANGO_ADMIN_PATH>/pict/integrationrevision/` вместе с их вложенными адресами и именами URL вызывают те же обработчики. GET-параметры и POST сохраняются, действуют те же проверки доступа и CSRF. Ссылки в админке используют маршруты `sitecontent`.

Пустое поле «Страницы» означает все публичные страницы, использующие `pict/base.html`. Для ограничения указываются точные локальные пути, по одному на строку: `/`, `/about/`, `/designer/`, `/skinali/`, `/skinali/<slug>/`. Конечный слеш значим; `/skinali/` не включает категории автоматически. Параметры запроса игнорируются: `/about/?source=mail` соответствует `/about/`. Домены, query string, фрагменты, пробелы внутри пути и маски запрещены. Повторяющиеся строки удаляются при валидации. Старое значение `/designer` при сохранении нормализуется в `/designer/`. Нормализация и сравнение находятся в `pict.page_paths`: параметр `allow_subpaths` по умолчанию выключен для интеграций, а встроенный квиз явно включает его для конечных масок `/*`.

Сохранение включённой интеграции сразу меняет последующие ответы сайта. Для отключения снимите «Включена» и сохраните. Удаление через admin запрещено, чтобы сохранять историю. Квизы в виде всплывающих виджетов подключаются этим механизмом; для квиза внутри конкретного блока страницы нужна отдельная область в её шаблоне, здесь такие области не добавлены.

## Модели и история

`Integration` и `IntegrationRevision` определены в `sitecontent/models.py`. Миграции переноса сохраняют таблицы `pict_integration` и `pict_integrationrevision`, созданные в `pict/0025_integrations`, а также идентификаторы записей, историю версий и ссылки журнала admin. [Миграции](../migrations/README.md#pict0040_remove_integration_state-и-sitecontent0017_move_integrations).

`Integration.SNAPSHOT_FIELDS` задаёт единый список версионируемых полей для формы, снимков, просмотра и восстановления. `clean()` нормализует пути и запрещает включать запись без кода.

`save_with_revision(user, note)` валидирует и атомарно сохраняет интеграцию вместе со снимком JSON. Снимок содержит все редактируемые настройки; версия дополнительно хранит время, автора (`SET_NULL` при удалении пользователя) и действие. Все сохранения через admin используют этот метод. Прямой ORM `save()`/`update()` его не вызывает: служебный код, которому нужна история, обязан использовать `save_with_revision()`.

Ссылка «Открыть историю версий» ведёт в фильтрованный, постраничный список по адресу `/<DJANGO_ADMIN_PATH>/sitecontent/integrationrevision/`. Версии доступны только для чтения. Маршрут `admin:sitecontent_integrationrevision_restore` по GET показывает настройки и состояние включения, а по POST с CSRF восстанавливает все поля и создаёт новую версию. Предыдущие версии сохраняются. Восстановление также записывается в стандартный журнал Django Admin.

## Вывод и доступ

`pict/templatetags/integrations.py` регистрирует `site_integrations(context)` и читает модель `sitecontent.Integration`. Тег вызывается один раз в базовом шаблоне, выполняет один запрос включённых записей и сравнивает `request.path_info` со списком путей. Результат используется во всех трёх местах вставки. Межзапросного кеша нет, поэтому изменения видны сразу и не требуется синхронизация кеша между процессами. Без request или для namespaces `admin`/`djdt` тег возвращает пустой список без запроса.

HTML/JS выводится через `safe` только в публичном базовом шаблоне. Содержимое не компилируется как Django-шаблон: `{{ ... }}` и `{% ... %}` остаются буквальным текстом. Редактирование разрешено только активным суперпользователям, даже если обычному сотруднику выданы стандартные права этих моделей. Это доверенный исполняемый код в браузере посетителя: произвольные скрипты не проходят санитарную очистку, поскольку очистка сломала бы назначение интеграций.

Миграция `quiz/0002_seed_skinali_quiz` отключает включённую запись LeadForms №2327 после переноса квиза в приложение. Запись и прежние версии не удаляются; создаётся новая версия отключённого состояния с пояснением. Автоматическое обратное включение при откате не выполняется, чтобы не перекрыть более позднее решение администратора.

`sitecontent.forms.IntegrationAdminForm` использует экранируемые текстовые поля для кода с моноширинным шрифтом и выключенной проверкой орфографии. Значения в просмотре снимков и подтверждении восстановления тоже экранируются. `sitecontent/admin.py` регистрирует обе модели и открывает форму подтверждения из `templates/admin/sitecontent/integration/restore.html`. В хлебных крошках подтверждения ссылка на приложение строится по метаданным модели.

Дополнительные Python-пакеты, Redis и фоновые задачи не нужны. Один запрос небольшого списка подходит для текущей нагрузки 10–20 посетителей; загрузка сторонних скриптов влияет преимущественно на браузер.

## Проверки

`pict.tests.IntegrationTests` проверяет позиции и однократный вывод кода, отсутствие повторной интерпретации Django-тегов, пути и query string, немедленное отключение, один SQL-запрос и порядок, валидацию, сохранение автора версии, экранирование содержимого в admin и атомарность записи снимка. Проверки админки охватывают размещение «Интеграций» в `sitecontent`, штатные хлебные крошки списка, карточки и журнала, запрет доступа сотрудникам по обоим наборам адресов и восстановление версии по прежнему адресу с проверкой CSRF и созданием нового снимка.
