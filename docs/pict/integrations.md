# Интеграции публичного сайта

## Управление

Суперпользователю в Django Admin доступен раздел «Интеграции». Каждая запись объединяет название, описание, флаг включения, порядок, список страниц и три поля HTML/JavaScript: перед `</head>`, сразу после `<body>` и перед `</body>`. Новые записи выключены по умолчанию. При одинаковом порядке первой подключается запись с меньшим ID.

Пустое поле «Страницы» означает все публичные страницы, использующие `pict/base.html`. Для ограничения указываются точные локальные пути, по одному на строку: `/`, `/about/`, `/designer`, `/skinali/`, `/skinali/<slug>/`. Конечный слеш значим; `/skinali/` не включает категории автоматически. Параметры запроса игнорируются: `/about/?source=mail` соответствует `/about/`. Домены, query string, фрагменты, пробелы внутри пути и маски запрещены. Повторяющиеся строки удаляются при валидации.

Сохранение включённой интеграции сразу меняет последующие ответы сайта. Для отключения снимите «Включена» и сохраните. Удаление через admin запрещено, чтобы сохранять историю. Квизы в виде всплывающих виджетов подключаются этим механизмом; для квиза внутри конкретного блока страницы нужна отдельная область в её шаблоне, здесь такие области не добавлены.

## Модели и история

`Integration` и `IntegrationRevision` определены в `models.py`, таблицы добавляет миграция `0025_integrations`. `Integration.SNAPSHOT_FIELDS` задаёт единый список версионируемых полей для формы, снимков, просмотра и восстановления. `clean()` нормализует пути и запрещает включать запись без кода.

`save_with_revision(user, note)` валидирует и атомарно сохраняет интеграцию вместе со снимком JSON. Снимок содержит все редактируемые настройки; версия дополнительно хранит время, автора (`SET_NULL` при удалении пользователя) и действие. Все сохранения через admin используют этот метод. Прямой ORM `save()`/`update()` его не вызывает: служебный код, которому нужна история, обязан использовать `save_with_revision()`.

Ссылка «Открыть историю версий» ведёт в фильтрованный, постраничный список. Версии доступны только для чтения. В карточке версии есть ссылка восстановления: GET показывает настройки и состояние включения, POST с CSRF восстанавливает все поля и создаёт новую версию. Предыдущие версии сохраняются. Восстановление также записывается в стандартный журнал Django Admin.

## Вывод и доступ

`templatetags/integrations.py` регистрирует `site_integrations(context)`. Тег вызывается один раз в базовом шаблоне, выполняет один запрос включённых записей и сравнивает `request.path_info` со списком путей. Результат используется во всех трёх местах вставки. Межзапросного кеша нет, поэтому изменения видны сразу и не требуется синхронизация кеша между процессами. Без request или для namespaces `admin`/`djdt` тег возвращает пустой список без запроса.

HTML/JS выводится через `safe` только в публичном базовом шаблоне. Содержимое не компилируется как Django-шаблон: `{{ ... }}` и `{% ... %}` остаются буквальным текстом. Редактирование разрешено только активным суперпользователям, даже если обычному сотруднику выданы стандартные права этих моделей. Это доверенный исполняемый код в браузере посетителя: произвольные скрипты не проходят санитарную очистку, поскольку очистка сломала бы назначение интеграций.

`IntegrationAdminForm` использует текстовые поля для кода с моноширинным шрифтом. В admin значения экранируются как в редакторе, так и при просмотре снимков и подтверждении восстановления; предпросмотра с выполнением скриптов нет. Основной шаблон на диске не редактируется из admin.

Дополнительные Python-пакеты, Redis и фоновые задачи не нужны. Один запрос небольшого списка подходит для текущей нагрузки 10–20 посетителей; загрузка сторонних скриптов влияет преимущественно на браузер.

## Проверки

`IntegrationTests` проверяет позиции и однократный вывод кода, отсутствие повторной интерпретации Django-тегов, пути и query string, немедленное отключение, один SQL-запрос и порядок, валидацию, сохранение автора версии, экранирование опасного содержимого в admin, запреты для сотрудников с правами моделей, GET/POST и CSRF при восстановлении, новую версию при откате и атомарность при ошибке записи снимка.
